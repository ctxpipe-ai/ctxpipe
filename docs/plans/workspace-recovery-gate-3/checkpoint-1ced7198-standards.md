1. **[P1, documented behavior breach] Native migration export omits its required follow-up jobs.** Both the no-op branch (`workspace-migration-export.ts:133-158`) and committed branch (`:188-205`) enqueue hydrate and complete, but neither schedules bootstrap or import-key cleanup. The generic predecessor still does this through `postExportFollowUpKinds` (`workspace-write-commit.ts:504-516,679-691`). The locked migration contract requires “Then enqueue bootstrap” (`12-first-project-migration.md:78`), and ADR-033 requires preservation of that product behavior. New and migrated workspaces can therefore finish export without the canonical `AGENTS.md`/knowledge skill and retain migration-only keys. Add durable, idempotent follow-up enqueue steps after publication for both real and no-op exports.

2. **[P1, documented data-loss breach] Export silently drops linked remotes on filename collisions.** `migration-export.ts:31-44` derives `repositories/<last-segment>.md` and simply continues when that path is occupied; `planMigrationExport` uses this helper at `:602-607`. Two distinct remotes named `api.git`, or a new `api.git` remote plus an existing declaration at `repositories/api.md`, yield no declaration for the later remote. This violates the migration requirement to export `repositories/*.md` for the Workspace’s linked set (`12-first-project-migration.md:78`) and the one-file-per-linked-remote contract (`02-hydration-contract.md:45`). Reuse the canonical validated URL and collision allocator from `changeLinkedRepository`, including `-2`, `-3`, … paths.

3. **[P2, correctness defect] A null import key falsely converges.** `hydrate-write-jobs.ts:192-197` returns early when `parsed.attributes.import_key == null`, so valid YAML containing `import_key: null` is neither removed nor counted by the cleanup remainder. Detect key presence rather than value truthiness and prove the native cleanup deletes null and empty nodes.

**Result:** three blocking correctness findings: two documented P1s and one P2. The prior credential/URL, GitHub-case identity, ambiguous-folder, claims-alias, removed-anchor, and YAML-boundary defects are fixed in the pinned blobs.
