# Gate 3 checkpoint — Spec review

Reviewed `bb24210c01e0dc1bcbc2d4fdf197d07a7a17035d...e7c18bd854a54f7d8190c663a014c5f0158ed67e` from exact Git blobs. This is an intermediate review of bootstrap and UI file edits only.

1. **[P1] A stale no-op silently completes.** Spec: “Target the remote’s **default branch**” and “No file changes → skip” (issue 10, lines 74, 77). Both workflows decide no-op from the acquired SHA and immediately set `completed` (`workspace-bootstrap.ts:188-192`; `workspace-file-edit.ts:218-223`), bypassing every live generation/URL/default/tip fence in `broker-push`. If the branch advances or relinks after acquire, an edit that was equal at the old SHA can be lost. Recheck binding plus actual default tip before `complete-no-op`; retry/rebase when the tip changed.

2. **[P1] Lost-push recovery fails once the branch advances past the recorded commit.** Spec: “If origin already has it, skip push and hydrate. Don’t recommit” (issue 10, line 120). `broker-push` accepts only `tip.sha === committed.sha` and rejects any other desired/tip SHA (`workspace-bootstrap.ts:317-342`; file-edit equivalents `358-383`). After push B succeeds, its acknowledgement is lost, and C is pushed atop B, retry fails although origin contains B. Fetch the branch and test reachability of the persisted commit; then hydrate the canonical tip without repushing.

3. **[P1] A publication CAS miss still completes without hydration.** ADR-033 says “completed status follows successful publication” and hydration “retries independently” (line 14); issue 10 says “Hydrate the new SHA” (line 128). If `captureWorkspaceRevision` loses its CAS and current desired is neither the old nor committed revision, `published` is `null`; both workflows skip `enqueue-hydrate` but still call `persistWriteJobCommitSha`, which sets `completed` (`workspace-bootstrap.ts:398-442`; file edit `439-483`). A null publication must not enter `completed`; reconcile the current canonical revision and durably enqueue hydration, or retain a retryable/superseded outcome.

4. **[P1] Native failures leave durable job state stuck.** Spec: conflict failure “fails **that job**” (issue 10, line 82), and Gate 3 requires “one durable result” (plan, lines 653-654). The new workflows claim `running` but have no failure finalizer; default/relink/non-FF exhaustion leaves that status indefinitely. Admission failure after `persistBoundWriteJob` likewise returns false while leaving `queued` (`enqueue-workspace-write-commit.ts:143-164`). Persist an appropriate failed/paused terminal state only after OpenWorkflow exhausts retry, and make enqueue failure resumable rather than orphaned.

The documented ten unmigrated kinds, protected/paused resume, semantic merge/restart depth, alternate writers/credentials, and explicit subject-model work remain known Gate 3 scope and are not counted above.
