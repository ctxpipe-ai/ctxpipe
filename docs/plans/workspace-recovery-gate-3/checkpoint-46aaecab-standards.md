1. **[P1, documented behavior breach] Workspace rename never reaches `AGENTS.md`.** `folder-map.ts:29-36` uses `displayName` only when `AGENTS.md` is absent; an existing document's `name` node is never updated. Yet `workspace-lifecycle.ts:95-107` handles rename solely by enqueueing `ops_folder_map`, and hydrate later copies that front-matter name. A renamed workspace therefore rehydrates its old display name. This violates the locked hydration contract (`02-hydration-contract.md:44`: ops updates `name` and the marked map) and ADR-033:19's product-behavior requirement. Mutate only the existing `name` YAML node while preserving the rest, and prove a real rename → native commit → hydrate cycle.

2. **[P1, documented behavior breach] A predicate claim still deletes the permanent Layer-1 link.** `hydrate.ts:158-191` emits the predicate claim, then suppresses a body `LINKS_TO` whenever *any* claim resolves to that target. The new fallback fixes predicate-less claims, but `[API](api.md)` plus `{to: api.md, predicate: DEPENDS_ON}` still projects only `DEPENDS_ON`. The locked contract calls relative Markdown links permanent Layer 1 (`02-hydration-contract.md:34-39`); ADR-033:19 requires preserving it. Suppress the body edge only when a `LINKS_TO` edge already exists, and prove both edges with a resolvable target.

3. **[P2, documented behavior breach] Valid Git folder names can make folder-map maintenance non-convergent.** `folder-map.ts:4-15` decodes link destinations and rejects `#`, `?`, or `:`, while lines 115-127 emit those paths percent-encoded. For a tracked `a#b/file.md`, the first run adds `[a#b/](a%23b/)`; the next run rejects that reference and appends the same entry again. Parentheses also produce ambiguous Markdown destinations. This contradicts full-path identity (`03-knowledge-file-layout.md:30`) and the required no-change skip (`10-ingest-to-git-write-protocol.md:77`). Compare normalized repository paths without rejecting decoded legal characters and emit robust Markdown destinations.
