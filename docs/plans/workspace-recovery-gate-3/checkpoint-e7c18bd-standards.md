# Gate 3 checkpoint — Standards review

Pinned range: `bb24210c01e0dc1bcbc2d4fdf197d07a7a17035d...e7c18bd854a54f7d8190c663a014c5f0158ed67e`

1. **[P1, documented breach] A pushed job can be marked completed without scheduling hydration.** In `workspace-bootstrap.ts:427-440` and `workspace-file-edit.ts:468-481`, `if (published)` guards only `enqueue-hydrate`; `persistWriteJobCommitSha` runs unconditionally. A binding/default/generation change after the final broker check can make `captureWorkspaceRevision` and its fallback return `null` after the Git push succeeded. The workflow then skips hydration and records `completed`. This violates ADR-033 lines 14-16 (hydrate the committed revision; completion follows publication) and `docs/plans/workspace-recovery-gate-3/status.md:24` (completion follows durable hydrate enqueue). Treat a missing published revision as a non-completed conflict/failure, and make successful durable hydrate enqueue a precondition of completion.

2. **[P2, documented behavior breach] UI edits overwrite Git file modes.** `workspace-file-edit.ts:229-244` stages every written path as `100644`. Saving executable text therefore changes `100755` to `100644`; editing a symlink changes `120000` into a regular file. That is an extra repository mutation beyond the requested content edit and conflicts with ADR-033 line 18's requirement to preserve product behavior. Read the existing tree entry and retain its mode for updates; use `100644` only for new ordinary files. Add native proof for an executable-file save (and define/reject symlink edits explicitly).

3. **[Judgement call — Duplicated Code] The two workflows copy the durable write protocol.** `workspace-bootstrap.ts:70-442` and `workspace-file-edit.ts:92-483` duplicate acquisition, pack restoration, tree construction, deterministic commit creation, broker admission/replay, push, revision capture, hydrate enqueue, and completion. With ten kinds still pending, fixes such as finding 1 already require parallel edits and can diverge. Extract shared typed helpers for acquisition, staging primitives, commit construction, broker push, and publication; keep each registered workflow's named `step.run` sequence explicit so ADR-033's “no second runner state machine” boundary remains intact.

**Result:** two blocking correctness/standard findings and one refactoring smell. This is an intermediate checkpoint review, not terminal Gate 3 acceptance.
