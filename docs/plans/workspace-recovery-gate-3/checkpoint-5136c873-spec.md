# Spec review — `bb24210c...5136c873`

## Findings

1. **[P1] A successfully rebased published session branch can no longer publish.** `conversation-publish.ts:169-189` always chooses the remote session tip as the thin-pack base when that branch exists, then requires it to be an ancestor of local `HEAD`. A rebase rewrites the session commits, so this test fails and Push/Create PR returns “restore its current revision.” Ticket 14 requires “dirty tree → rebase onto the new SHA if it applies” and permits force-with-lease on the session branch (`14-worktree-and-agent-change-lifecycle.md:80,90,116`). Keep the lease on the observed session tip, but choose a locally present remote exclusion that is an ancestor—session tip when possible, otherwise the captured desired/default SHA—and prove published branch → default advances → successful rebase → publish.

2. **[P1] PR binding is still torn across separate read snapshots.** `conversationSelection` validates the stored number against the current workspace (`models/conversations.ts:30-43`), but list/detail then separately reload the workspace and construct the URL from that later row (`routes/v1/conversations.ts:451-468,486-512`). A relink A→B between statements produces `B/pull/41` from A’s valid #41. GET PR has the same gap before its provider read (`:722-749`); a matching deterministic branch name does not identify the repository generation. ADR-033 requires that “Read projections hide old or unbound numbers after relink” (`ADR-033-native-durable-write-workflows.md:20`). Pair the number with its validated saved revision URL or recheck one binding snapshot after the read; add an inter-query relink barrier.

3. **[P1] Finalization can overwrite the provider directory with stale identity after releasing its locks.** Notion and Linear commit their fenced connection update, then call `upsertConnectionDirectory(updated)` with that old row (`notion-connector.ts:960-1008`; `linear-connector.ts:1267-1315`). If a provider update commits and projects identity B before this call, the finalizer writes identity A afterward (`connection-directory.ts:46-73`), breaking webhook discovery. This defeats ADR-033’s provider-identity-under-lock guarantee (`:25`). Remove the redundant directory write for setup-phase-only changes, or re-read/CAS current identity before projection.

The Files PUT→Push correction is complete; static PR collisions, unbound migration rows, and the two tested depth-one cases are covered. Declared open Gate 3 inventory was not counted.
