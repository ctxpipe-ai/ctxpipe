## Findings

1. **[P1] Claims-only extraction can rewrite `AGENTS.md` instructions.** The new removal of the `AGENTS.md` filter in `workspace-extract-ingest.ts:140-145` correctly makes repository-subject claims publishable, but the claims-only path calls `mergeExistingImportedMarkdown` (`migration-export.ts:672-687`). For an existing file with front matter, that helper rebuilds the body with `input.body.trim()` (`migration-export.ts:103-109`). Leading indentation, deliberate blank lines, trailing spaces, and the final-newline shape are therefore changed even though extraction is only adding metadata; a body whose first instruction is an indented Markdown block can change meaning. The added contract checks `toContain` (`write-extract-native.contract.test.ts:694-708`), so it misses the rewrite. This conflicts with ADR-033:46: **“Repository-subject claims may update AGENTS.md metadata through the same owner-preserving merge; extraction does not rewrite its instructions.”** Apply the claims merge directly to the original bytes (the existing `updateKnowledgeMetadata` API preserves the body), and assert the body suffix byte-for-byte.

2. **[P2] Root-equivalent dot fragments still produce distinct evidence identities.** `extractionEvidencePath` now normalizes internal dot segments, but returns `"./"` for `#./` and `"."` for `#src/..`, while the equivalent repository-only source returns `""` (`retract-extraction.ts:21-39`). `planCapturedExtraction` includes that value in claim identity (`plan-extraction.ts:68-80`), so a historical `repo#./` claim and a new repository-scoped claim do not merge and can leave duplicate YAML entries. The new proof covers only a non-root path (`write-extraction-retraction-native.contract.test.ts:165-170`). This conflicts with ADR-033:53: **“Evidence identity normalizes equivalent relative and repository URL paths before merging claims.”** Canonicalize normalized root (`.`/`./`) to `""` for URL and relative evidence and add merge/replay coverage.
