**Decision:** fail for implemented scope — 2 high-priority findings.

## Findings

**[P1] Upgrade compatibility does not recover config owners that already crossed the old no-change transition — `apps/backend/src/openworkflow/workflows/notion-sync-config.ts:32-41`, `linear-sync-config.ts:39-48`; `apps/backend/src/models/connector-content-sync.ts:242-267`.** At e947, Notion durably cached `persist-config-pr-state` before enqueueing content; both Notion and Linear could therefore crash with the row already `initial_sync` and no content owner. On replay after this upgrade, the newly inserted first capture step requires `awaiting_merge && pendingConfigPrCreating`, rejects that owner, and reconciliation does not inspect config owners outside that state (`connector-content-sync.ts:305-348`). Pre-checkpoint Confluence no-change runs can likewise already be `live` without a content child, with no migration/backfill here. ADR-033:11 says **“OpenWorkflow owns execution and retry,”** and line 25 says **“Generation-zero compatibility applies to old persisted inputs and cached capture results”** and **“unchanged config admits full content work for every provider.”** Add a binding-fenced compatibility path/backfill that idempotently admits the missing content owner from eligible old no-change results, while retaining draft/stale rejection.

**[P1] A content owner canceled before activation permanently poisons admission — `apps/backend/src/openworkflow/enqueue-connector-content-sync.ts:63-76`; `apps/backend/src/models/connector-content-sync.ts:145-147,349-359`.** If the generation-N+1 run becomes failed/canceled before its first activation commits, `activateConnectorContentSync` returns false, but the helper ignores that result and reports `true`. The connection remains generation N with no owner; reconciliation searches N, while every retry reuses the same N+1 idempotency key and terminal run, again returning success without activation. ADR-033:25 promises **“Content admission creates a generation-scoped native owner before publishing initial_sync,”** **“the workflow repeats activation as its first durable step,”** and **“Current native failed/canceled owners project setup failure.”** Persist/reconcile the terminal owner before acknowledging, or return non-acceptance and admit a fresh bounded owner.

## Verified

The three e947 findings are closed for new runs: all no-change config workflows use shared native admission; missing generations/cached content captures normalize to zero; terminal reconciliation checks persisted full binding and Forge cloud/base replacement advances generation. Earlier publication/PR/directory fixes remain intact. Declared proposal-admission, event-ordering, and remaining Gate 3 inventory were excluded; this is not gate acceptance.
