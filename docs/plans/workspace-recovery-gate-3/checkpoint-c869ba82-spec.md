## Findings

**[P1] Retraction destroys per-source signal history before evaluating it.** The hydration contract requires “one signal per asserting path” with independent windows (`.ai/scratchpad/git-backed-projects/issues/02-hydration-contract.md:64-69`). `planCapturedExtraction` first calls `planKnowledgeProjection`, then retracts its output (`plan-extraction.ts:56-99`). That projection unions claims only on `(to, predicate)` and overwrites `source` (`dest-workspace-first.ts:157-188`); the YAML merge also selects the first node using only those fields (`migration-export.ts:125-147`). If a file has identical `CALLS` claims from `#src/a.ts` and `#src/b.ts`, a full capture returning only b rewrites a to b, leaves the existing b duplicate, and retraction sees both as asserted. With a new source c, a’s historical signal is silently replaced instead of receiving `valid_to`. Key extraction claims by canonical source identity as well as endpoints/predicate, and retract against the original claim set before adding/reasserting current signals. Add native same-relation/different-source disappearance and source-change cases.

**[P1] Partial retraction misses changed files beneath a captured source directory.** ADR-033 says partial retraction “expires absent in-scope claims” (`.ai/memory/decisions/ADR-033-native-durable-write-workflows.md:43`). The capture helper treats `provenance.path` as a file (`extraction.ts:106-118`), while API claims use that field for an API directory (`identifyApiClaims.ts:88-122`). The scope check only matches when the claim path equals or descends from a changed path (`retract-extraction.ts:95-99`). Thus changing `apps/web/api/route.ts` does not scope the existing source `#apps/web/api`; a removed endpoint remains evergreen. Persist whether provenance is a file or directory (and retain usable root scope), then test path intersection in the correct direction with a native partial endpoint removal.
