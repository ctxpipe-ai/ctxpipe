# Spec review — `bb24210c...1fee4b71`

## Findings

1. **[P1] Commit+Push can publish a stale sandbox into a rebound repository.** `conversation-files-routes.ts:530-550` reuses any ready handle, then loads the *current* revision; it never compares the registered sandbox’s captured URL/generation/SHA/default. `conversation-publish.ts:86-100` only compares that current revision back to current DB state (and explicitly substitutes the current SHA). If relink races sandbox destruction, repository A’s tree can therefore be pushed to repository B. The locked lifecycle says, “Relink or desired-URL change → destroy now” and “Relink (URL/generation change) still destroys” (`14-worktree-and-agent-change-lifecycle.md:102`). Require captured sandbox identity on this route and fence it before packing/credential issuance; add the missing stale **push** HTTP case (the current `stale` matrix selects only `pull-request`, `conversation-publish-native.contract.test.ts:81-96`).

2. **[P1] Relink after branch push can still create an old-repository PR.** In `conversations.ts:813-821` the brokered branch push can finish, then `:823-857` reads/creates a PR using the earlier repository/connection/default without another binding check; `:858-862` persists that stale result without a binding CAS. Trigger: pause immediately after `pushConversationSessionBranch`, relink A→B, resume. This violates “Relink: do not push a PR to the old URL (generation recheck)” (`14-worktree-and-agent-change-lifecycle.md:80`). Recheck the full binding immediately before the PR API mutation and fence result persistence; prove this exact barrier race.

3. **[P1] The native object handoff rejects ordinary large repositories and is not actually memory-bounded.** `conversation-publish.ts:130-142` packs every object reachable from HEAD (no excluded base), base64-collects all stdout, and only afterward rejects over 8 MiB. A depth-1 repository with a >8 MiB incompressible base blob cannot publish a one-byte chat edit, while potentially buffering far beyond the limit. The contract is that the backend “creates the branch + PR from the sandbox tree” (`14-worktree-and-agent-change-lifecycle.md:73`), with a 4 GiB chat sandbox (`:104`). Transfer a bounded delta against a broker-fetched base/session tip and test a large base plus tiny edit.

The three prior checkpoint findings are fixed: native-owned paused jobs cannot be claimed, queued owners reconcile terminal state, Files admits unavailable writes, and successful hydrate owns export follow-ups using the export’s read revision. Declared remaining Gate 3 inventory was treated as open scope, not a checkpoint defect.
