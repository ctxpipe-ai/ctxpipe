# Spec review — `bb24210c...e5c80246`

## Findings

1. **[P1] Thin-pack publication fails after restoring an existing session branch.** `conversation-publish.ts:164-169` always subtracts `revision.sha`. After idle/loss, however, `workspace-chat-turn-runtime.ts:103-116` clones the existing session branch; TanStack clones are shallow by default (`17-tanstack-sandbox-not-diy-opencode.md:35`), so the default SHA is normally absent and `git pack-objects ... ^<defaultSha>` fails with `bad object`. This breaks both later edits and Create PR on an already-pushed branch, contrary to “After idle, check out the existing session branch” (`14-worktree-and-agent-change-lifecycle.md:94`). Select an exclusion proven present locally and fetched by the broker—normally the observed remote session tip—and test publish → destroy → depth-one session restore → edit/publish and Create PR.

2. **[P1] Files can warm and edit a sandbox that the corrected publisher refuses.** `conversation-files-routes.ts:330-398` lets `readySandboxHandle` create a missing sandbox, but `warmConversationSandbox` returns only the memoized handle and never registers its captured metadata. PUT then succeeds (`:479-520`), while POST Push now requires `getRegisteredChatSandbox(...).handle` and returns `missing_sandbox` (`:522-552`). The spec names the file-edit panel as an “explicit publish path” (`14-worktree-and-agent-change-lifecycle.md:78`). Register the warmed handle and binding together; prove no-prepare PUT → Push.

3. **[P1] Stored PR identity is still not bound to repository generation.** Only `lastChatPrNumber` is stored. After repo A PR #41 and relink to B, `conversations.ts:818-845` queries B’s #41 and accepts any open result without checking its head branch; an unrelated PR can be returned/persisted instead of creating one for the session branch. GET has the same ambiguity (`:730-753`), and `conversationPublicPrUrl` builds a new-repo URL from the old number (`conversation-files-routes.ts:620-630`). This misses the explicit requirement to “bind PR to repo generation” (`14-worktree-and-agent-change-lifecycle.md:112`). Persist PR binding identity or clear/re-resolve it on relink; test a same-number collision across repositories.

The prior stale-handle, post-push relink, and large-base failures are closed for their original triggers. Repository API tokens are explicitly scoped, and config writers recheck the actual default before mutation. Declared remaining Gate 3 work was not counted.
