# Spec review — `c4caa83503c4ea1cd1648c86de6574f3107f8144`

Four findings (three P1, one P2).

- **[P1] Two HTTP paths still acknowledge before durable ingestion admission.** ADR-033 says, “queued status is published only after OpenWorkflow accepts that key” (`ADR-033`, line 45). `repositories.ts:323-329` and `connectors-atlassian.ts:992-999` discard `enqueueRepositoryIngestionWorkflow(...)` with `void`, then return success. A process loss can leave only the prepared request and no native owner; an enqueue rejection also becomes an unhandled promise rejection. Await admission, as the other repository/connector callers do, and make the HTTP result reflect whether ownership was durably accepted.

- **[P1] A superseded producer can still publish a stale codesearch index.** Ticket 11 requires: “Publish `indexed SHA` only if ... membership/ref, and current desired SHA still match the job. Otherwise discard” (lines 94-96). `repository-ingestion.ts:246-258` starts `repository-index` without the request identity. That child checks only repository/URL on entry (`repository-index.ts:147-170`) and performs clone/Zoekt/SCIP mutations through lines 232-326 without a current-owner recheck. If branch-A ingestion is superseded by branch B while A is indexing, A can finish last and replace B’s index. Carry the immutable request/binding through the child and fence publication/side effects, or publish the completed index under the required CAS.

- **[P1] Follow-up planning changes “use the default” into the old branch name.** Ticket 11 defines missing `branch` as “remote default” (lines 82-84). For an input with `targetBranch: null`, `repository-ingestion.ts:605` passes `result.sourceBranch`. If the default changes from `main` to `trunk` during ingestion, the follow-up resolves `main`, may see no change, and never ingests `trunk`. Preserve the nullable requested ref when enqueuing the successor.

- **[P2] Encoded source paths do not converge with legacy source spelling.** Ticket 2 requires “one signal per asserting path” (line 64). New claims encode path segments (`plan-extraction.ts:79`), but merge identity compares the raw source string (`:65-66`, `migration-export.ts:135-140`). Thus existing `#src/a#b.ts` plus incoming `#src/a%23b.ts` yields two active claims, although retraction decodes both to the same path. Canonicalize repository URL + first-fragment-decoded path for identity.

The prior source-specific-history and directory-overlap defects are otherwise corrected. Declared live-producer, endpoint, direct transport-ACK, config-ordering, unborn-bootstrap, allocation, semantic uncertainty, and cleanup work remains open; this is not Gate 3 acceptance.
