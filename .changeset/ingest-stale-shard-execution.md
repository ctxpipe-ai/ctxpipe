Ingestion v2: a stale execution of a workflow run stops before its next step attempt. When a worker does not extend the lease of a run in time, another worker starts a second execution of the run. Before, the first execution continued and made its own model calls for up to three attempts of the step. Now each step attempt first makes sure that its execution still owns the run. If it does not, the step makes no model call, and the worker logs `ingestion-v2.execution-lease-lost`. A stale execution does no cleanup while another execution owns the run. The live execution uses the same scratch folders and cleans them up. After a cancel, the run releases its scratch folders at once. When the worker cannot read the run, the step continues and logs `ingestion-v2.execution-lease-check-failed`. Each step event now has the execution attempt (`executionAttempt`) when the worker knows it, and the `ingestion.step` span has `openworkflow.execution.attempt`. With these values, a query can drop the events of a stale execution. The span also records an adoption of the work of another execution (`ctxpipe.ingest.adopted`). It keeps `error.type` only when the step ends partial. A failed lease extension now writes the log event `openworkflow.lease_extend_failed`.
