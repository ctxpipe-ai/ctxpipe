The deployment target changes, but each path runs the same services: backend,
UI, worker, codesearch, PostgreSQL, a graph database, and a sandbox host.

## What each path provides

| | Docker Compose | AWS CDK | Terraform |
| --- | --- | --- | --- |
| Postgres | `pgvector/pgvector:pg17` container | Aurora PostgreSQL 16 | Neon PostgreSQL 17 |
| Graph database | FalkorDB container | Amazon Neptune | FalkorDB on Railway |
| Sandboxes | Docker-in-Docker (`dind`) | A Graviton EC2 Docker host | Vercel Sandbox |
| Public origin | Your TLS proxy in front of the backend | Route 53 and a load balancer | Railway domains |

## Shared requirements

- A public HTTPS origin, `AUTH_BASE_URL`, for the browser, auth, the API,
  connector callbacks, and MCP.
- PostgreSQL with pgvector, and a supported
  [graph database](/docs/self-hosting/graph-databases).
- Durable storage for the codesearch indexes and the repository clone cache.
- Model provider credentials for chat, ingestion, and embeddings. See
  [Models](/docs/self-hosting/models).
- A sandbox for Workspace chat and ingestion. Without one, chat answers `503`.
  For another platform, see
  [Chat sandboxes](/docs/self-hosting/configuration#chat-sandboxes).
- A provider app for each connector that you turn on: a GitHub App for
  repositories, and OAuth apps for Atlassian, Slack, Linear, Notion, and
  PagerDuty. See the source connector pages in this section.
