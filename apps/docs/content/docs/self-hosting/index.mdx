---
title: Self-host ctxpipe
description: Run the open-source core of ctxpipe on your own infrastructure, and know the services and the work that you own.
---

Self-hosted ctxpipe has the same product as hosted ctxpipe, inside
infrastructure that you control. ctxpipe the company is not in the data path:
your deployment holds the credentials and the source data, and model requests
go from your deployment to the provider that you choose.

## Choose a deployment path

| Path | Use it when | You operate |
| --- | --- | --- |
| [Docker Compose](/docs/self-hosting/deployment/docker) | You evaluate ctxpipe, or run a small internal deployment on one host. | One Compose project and its volumes |
| [AWS CDK](/docs/self-hosting/deployment/aws) | You run ctxpipe in your own AWS account. | The `CtxPipe` construct, a domain, and model access |
| [Terraform](/docs/self-hosting/deployment/terraform) | You want a starting point for Railway and Neon. It is the layout of hosted ctxpipe, so you must fork it. | Railway, Neon, Vercel Sandbox, and your CI |

Start with the [quickstart](/docs/self-hosting/quickstart). It covers each path.

## What you run

- **Backend**: auth, the REST API, the MCP endpoint, webhooks, and the public
  origin. It also serves the UI.
- **UI**: the web app, behind the backend.
- **Worker**: the background jobs for ingestion, connectors, and Workspace
  writes.
- **Codesearch**: repository clones and code search indexes, on persistent
  storage.
- **PostgreSQL with pgvector**: the application data and the job state.
- **A graph database**: FalkorDB by default.
- **A sandbox host**: runs Workspace chat and ingestion in isolated containers.

OpenTelemetry export is off by default. See
[Observability](/docs/self-hosting/configuration#observability).

## What you own

- One stable public HTTPS origin for the browser, the API, auth, MCP, and the
  provider callbacks.
- The backups and recovery of Postgres, the graph database, and codesearch.
- The secrets for auth, encryption, models, and connectors.
- The provider apps (GitHub, Slack, Linear, and so on) for the connectors that
  you turn on.
- Monitoring, migrations, upgrades, and rollback.

After the deployment is healthy, people use it like hosted ctxpipe. Point them
to [Connections](/docs/connections) and
[Connect your agent](/docs/mcp/mcp-docs).
