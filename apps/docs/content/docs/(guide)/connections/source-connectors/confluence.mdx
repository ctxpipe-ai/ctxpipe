<Callout title="Fully managed app flow">
  This page covers the fully managed ctx| app, where Atlassian OAuth and the
  Forge app install link are managed for you. Self-hosted deployments use the
  same product flow after setup, but must provide their own Atlassian OAuth and
  Forge configuration. See [Self-host Confluence & Atlassian](/docs/self-hosting/confluence-atlassian).
</Callout>

The **Confluence connector** turns Confluence pages into repo-backed context for
ctx|. Instead of reading every page in a site, you choose the spaces and pages
that should be available to agents.

ctx| connects to the selected Confluence site through Atlassian OAuth and the
ctx| Forge app. The connection holds authorization only. A source file in each
[Workspace](/docs/workspaces) holds the scope (the spaces and pages). ctx|
syncs the selected pages into the Workspace repository and indexes them like
any other knowledge file. When pages or spaces change in Confluence, the Forge
app notifies ctx| so the mirror is updated and indexed again.

Page attachments and explicit embedded external media are copied under
`confluence/<spaceKey>/_assets/<pageId>/` and linked relatively from generated
Markdown. Each asset is capped at 25 MiB and each page has a 100 MiB asset
budget. Unsafe, unavailable, or oversized media leaves a page link or textual
stub; Atlassian media and download URLs are never persisted.

## Prerequisites

Before starting, make sure you have:

- Access to a ctx| organization in the fully managed app.
- Permission to connect Atlassian OAuth for the Confluence site.
- Permission to install or request installation of the ctx| Forge app in
  Atlassian.
- A Workspace whose repository the ctx| GitHub App can write to. The
  repository must use format 2 or higher. If it does not, the Workspace shows
  **Upgrade this Workspace first**. See
  [Upgrades](/docs/workspaces/settings#upgrades).
- Permission to merge the pull request that adds the source.

<Callout title="Not sure whether you have the right access?">
  **Confluence:** open `admin.atlassian.com`, choose the Confluence site, then
  check whether you can reach **Connected apps** and install or manage apps for
  that site. Atlassian documents this as organization admin or site admin access.
  If you cannot see those controls, ask an Atlassian admin in your org to
  complete the Forge app install.

  **GitHub:** open the GitHub organization and try the GitHub App install flow
  for the repositories you want ctx| to read. You are ready if GitHub lets you
  install the app and choose repositories. If GitHub shows **Request** or
  **Install and request**, ask an organization owner to approve the installation.

  References: [Atlassian Connected apps](https://support.atlassian.com/organization-administration/docs/managing-an-installed-app/) and
  [GitHub App install requirements](https://docs.github.com/apps/using-github-apps/installing-a-github-app-from-a-third-party#requirements-to-install-a-github-app).
</Callout>

## Where the scope lives

The scope is in a source file in each Workspace, at
`sources/confluence/<name>.md`. The front matter holds the spaces. For each
space, `pages` is `all` or a list of page ids. The body is an optional
description of what the source is for.

```markdown
---
provider: confluence
connection: con_example
spaces:
  - key: ARCH
    pages: all
  - key: OPS
    pages: ["12345", "67890"]
---
```

- **Draft scope** is the file on the branch of the open pull request.
- **Live scope** is the file on the default branch after the merge.

ctx| keeps no second copy of the scope outside Git. Each Workspace has its own
scope. Mirrored pages are in `confluence/<spaceKey>/` in the Workspace
repository. The source owns these folders, so do not edit the files by hand.

## Setup flow

<Steps>
  <Step>
    ### Start from Connectors

    Open the ctx| fully managed app, choose the relevant organization, go to
    **Connectors**, select **Add connection**, then choose **Atlassian
    Confluence**.

    ctx| opens the Confluence setup wizard and tracks each task until the
    connector is ready.

    <ImageSlot
      title="Start Confluence setup"
      src="/add-connection-confluence.png"
      alt="Add Confluence connection from the ctx| Connectors page"
    />

  </Step>

  <Step>
    ### Link Atlassian account

    Link your Atlassian account with OAuth. This lets ctx| identify which
    Atlassian cloud site you are connecting and start the connector setup
    against that account.

    If the Atlassian account is already linked to another ctx| organization, the
    app may ask you to confirm or cancel the pending account claim.

    <ImageSlot
      title="Link Atlassian account"
      src="/link-atlassian-account.png"
      alt="Link Atlassian account step in the ctx| Confluence setup wizard"
    />

    <ImageSlot
      title="Authorize Atlassian OAuth"
      src="/atlassian-oauth.png"
      alt="Atlassian OAuth authorization screen for ctx|"
    />
  </Step>

  <Step>
    ### Install the Forge app

    After OAuth, install the ctx| Forge app in the Atlassian site. The Forge app
    is the Atlassian-side integration that lets ctx| read the Confluence content
    you explicitly select.

    You may need an Atlassian admin to complete this step. If you do not have
    admin permissions, ask an admin to install the app for the same Atlassian
    site before continuing.

    <ImageSlot
      title="Install the Forge app"
      src="/install-forge-app.png"
      alt="Install the ctx| Forge app in Atlassian Confluence"
    />
  </Step>

  <Step>
    ### Add to Workspaces

    The last step of the wizard is **Add to Workspaces**. Select the Workspaces
    that sync from Confluence. Then select the spaces and pages in the tree.
    Search with **Search spaces and pages...**. For each space, select all pages
    or only some pages. When you select more than one Workspace, choose **Same
    scope for each Workspace** or **A different scope for each Workspace**.
    Keep the scope intentional:

    - Start with the spaces your engineering team actively uses.
    - Exclude stale or sensitive areas that agents should not rely on.
    - Prefer authoritative docs over duplicates or abandoned pages.

    Choose **Add to Workspaces**. You can add the connection to a Workspace
    later. Expand the connector on **Connectors**. When no Workspace uses the
    connection, choose **Add to a Workspace**. Otherwise, choose **Manage**.
  </Step>

  <Step>
    ### Merge the pull requests

    ctx| opens one pull request for each Workspace. Each pull request adds
    `sources/confluence/<name>.md`. The dialog shows **Merge the pull request**
    (or **Merge the pull requests**) with a link to each one. Review the
    selected spaces and pages, then merge.

    After each merge, the dialog shows **Pull request merged**. The source does
    not sync before the merge. Then ctx| makes the first Confluence mirror.
    The Workspace indexes the new files after that.
  </Step>
</Steps>

<Callout title="Fully managed vs self-hosted">
  The fully managed app supplies the Atlassian OAuth app and Forge install URL.
  In a self-hosted deployment, you provide the Atlassian credentials, Forge
  setup, and GitHub app configuration.

  For self-hosted setup, go [here](/docs/self-hosting/confluence-atlassian).
</Callout>

## Change what syncs

Open the Workspace, then **Settings**. Find **Confluence** under **Sources**.
Each source has an edit, a rename, and a remove button. Each action opens a pull
request. See [Workspace settings](/docs/workspaces/settings#sources).

## Keeping content current

Choose **Sync now** in the menu of the connector card to start a full sync of
the Confluence sources of the connection. Only an owner or admin sees it. Use it
when change events did not arrive.

## Troubleshooting

### Add to a Workspace shows an error

- **Upgrade this Workspace first.** The Workspace repository does not use one
  file for each source yet. An owner or admin starts the upgrade in **Settings**,
  under **Upgrades**. Merge the pull request, then add the source again.
- **This Workspace is read-only.** ctx| cannot open a pull request. See
  [Write access](/docs/workspaces/settings#write-access).

### The source shows a status other than OK

Each source row in **Settings** shows **OK**, **Not valid**, **Connection
missing**, or **Out of access**, with a reason. See
[Source status](/docs/workspaces/settings#source-status).

### Removing the connector

Choose **Remove connector** in the menu of the connector card. This deletes the
ctx| authorization. The sources of the connection show **Connection missing**
and stop syncing. The source files and the files that ctx| already committed
stay in the Workspace repositories. Delete them in GitHub if you do not need
them.
