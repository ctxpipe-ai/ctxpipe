The **Linear connector** mirrors selected Linear teams and projects into a
[Workspace](/docs/workspaces) repository. ctxpipe requests read-only access. It
does not create or change Linear issues.

On a self-hosted deployment, the operator registers a Linear OAuth app first.
See [Self-host Linear](/docs/self-hosting/linear).

## What is mirrored

A team syncs its issues, projects, cycles, and labels. A project syncs its
issues from all teams. The mirror can include:

- issues and their comments, with the parent issue, the project milestone, and
  the relations to other issues (blocks, duplicate, related);
- project and initiative updates;
- cycles, labels, and the users that the content mentions;
- customer requests, unless you clear **Include customer requests**;
- attachments and embedded media, copied into git.

ctxpipe does not copy GitHub pull requests, commits, or diffs through Linear.
It keeps only the link. The GitHub connector already indexes that content.

<Callout title="Customer requests">
  Customer requests can contain the names and feedback of your customers. Each
  person who can read the Workspace repository can read them. Review the scope
  before you merge the pull request.
</Callout>

## Connect Linear

Follow [Add a tool to a Workspace](/docs/connections#add-a-tool-to-a-workspace).
For Linear:

1. On **Connectors**, select **Add connection**, then select **Connect** on the
   **Linear** row. Authorize the ctxpipe app in the Linear popup.
2. In **Add to Workspaces**, select the Workspaces, then the teams and
   projects. Clear **Include customer requests** to leave them out.
3. Merge the pull request that adds `sources/linear/<name>.md`.

To change the Workspaces or the scope later, choose **Manage** on the connector
card.

## Source file

```markdown
---
provider: linear
connection: con_example
teams: [ENG, OPS]
customerRequests: exclude
---

Engineering and operations work. Customer requests stay in the support Workspace.
```

## Files in the repository

Mirrored files are under `linear/`. Each team has a folder
`linear/teams/<TEAM-KEY>/`, and each project has a folder
`linear/projects/<id>/`. Below them are folders such as `issues/`, `documents/`,
`cycles/`, `labels/`, `users/`, and `customer-requests/`. The paths use stable
Linear ids, so a renamed issue or project does not make a second copy.

Attachments are in an `assets/` folder next to the Markdown file. Each asset
can be up to 25 MiB, and each Linear item up to 100 MiB in total. A file
that is too large, not safe, or not available stays a link to Linear.

## Check the setup

1. The Linear workspace shows on **Connectors**.
2. After the merge, the Workspace repository has files under `linear/`.
3. When you change a mirrored issue in Linear, the file of that issue changes. This
   step tests the Linear webhook.

For problems, see [Troubleshooting](/docs/connections#troubleshooting).
