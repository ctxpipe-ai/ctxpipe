title: Connected sources
description: What ctx| can connect today, how source content is scoped, and where agent access fits.
---

ctx| connects source systems, scopes what should be used, and writes the
result into a [Workspace](/docs/workspaces) as git files. GitHub is the
foundation: it hosts workspace repositories and the code repositories you link.

## Available today

| Source | How it works |
| --- | --- |
| **GitHub** | Hosts workspace repositories, indexes linked code repositories, and can mirror selected pull requests. |
| **Confluence** | Select spaces and pages, review draft `confluence/config.yaml` in a pull request, then merge it. Selected pages are mirrored into the Workspace. |
| **Slack** | Mention the bot in a thread (`app_mention`) to capture that thread as Markdown into the Workspace. Intent-based capture, not a channel mirror. |
| **Linear** | Select scope, review draft `linear/config.yaml` in a pull request, then merge it. Issues in scope are mirrored into the Workspace. |
| **Notion** | Select pages and databases, review draft `notion/config.yaml` in a pull request, then merge it. Selected content is mirrored into the Workspace. |
| **PagerDuty** | Select services, review draft `pagerduty/config.yaml` in a pull request, then merge it. Incidents from those services are mirrored as Markdown. |
| **Repo-native docs** | README files, `docs/**`, ADRs, `AGENTS.md`, skills, and similar files in linked repositories are indexed with the code. |

## What belongs in Git

Keep standards, decisions, and agent instructions close to the code when
possible. Good examples include:

- `README.md`, `CONTRIBUTING.md`, and files under `docs/**`.
- Architecture decisions such as `ADR-*.md`.
- Agent instructions such as `AGENTS.md`.
- Skills and other maintained team guidance.

This gives agents a better chance of finding the same source of truth your team
uses, instead of relying on duplicated notes or stale chat history.

## Agent access is separate

MCP clients are not source connections. Cursor, CI agents, and other MCP clients
connect to ctx| through the MCP endpoint, then ask about a Workspace.

For agent setup, see [ctx| MCP](/docs/mcp/mcp-docs).

## Roadmap

We expect more source connections over time, especially for engineering systems
that hold operational context. Examples include:

- Additional issue and project tracking systems, such as Jira.
- Error tracking and observability, such as Sentry.

Availability may differ between fully managed and self-hosted deployments.
Self-hosted operators must configure provider-owned OAuth applications and
webhooks before the corresponding connector is available — see
[Self-host Confluence & Atlassian](/docs/self-hosting/confluence-atlassian),
[Self-host Slack](/docs/self-hosting/slack),
[Self-host Linear](/docs/self-hosting/linear),
[Self-host Notion](/docs/self-hosting/notion), and
[Self-host PagerDuty](/docs/self-hosting/pagerduty).
