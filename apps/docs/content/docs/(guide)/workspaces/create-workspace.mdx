---
title: Create a Workspace
description: Choose or create the git repository that holds a Workspace's knowledge.
---

Add Workspace has two steps. Step 1 chooses the Workspace's **workspace
repository**. There is no draft step: once you pick a repository, the
Workspace exists and ctx| starts reading it. Step 2 adds the code
repositories and tools that the Workspace reads.

## Before you start

- Connect GitHub from **Connectors** if you want to pick or create a
  repository on GitHub. ctx| can only write to repositories the ctx| GitHub App
  can access.
- Decide which repository should hold this Workspace's knowledge. An empty
  repository is fine; so is an existing documentation repository.

## Create the Workspace

<Steps>
  <Step>
    ### Open Add Workspace

    Choose **+** next to **Workspaces** in the sidebar. Home also has
    **Create Workspace**: in the **Get started** guide, or on its own while
    your organization has no Workspace. After you connect GitHub from
    **Connectors**, the GitHub setup page also has **Create workspace**.
  </Step>

  <Step>
    ### Choose the repository

    Pick one of three ways:

    - **Select GitHub**: search the repositories the ctx| GitHub App can see.
      Sort by recently pushed, newest, oldest, or name.
    - **Create on GitHub**: opens GitHub's new-repository page. Create the
      repository, make sure the App can access it, then come back and select
      it.
    - **Paste URL**: any git URL. Repositories outside GitHub work as
      read-only Workspaces.

    To keep the Workspace in one folder of a larger repository, such as a
    monorepo, type that folder in **Root folder** (for example
    `docs/context`). Leave the field empty to use the whole repository. See
    [Root folder](#root-folder).

    Choose **Create Workspace**.
  </Step>

  <Step>
    ### Add code repositories and tools

    ctx| first checks that it can write to the workspace repository. Then it
    shows the **Sources** section of the new Workspace:

    - Choose **Add repositories** under **GitHub** to link
      [code repositories](/docs/workspaces/linked-repositories).
    - Choose **Add** next to a connected tool, such as Linear or Notion.
    - Choose **Add another connection**, or **Add connection** when no tool
      is connected, to connect a new tool. This closes Add Workspace.

    Each change goes to `.ctxpipe/sources.yaml` in the workspace repository,
    as a pull request or a direct commit. This step is optional. You can make
    the same changes later in **Settings**. Choose **Open Workspace** to
    finish.
  </Step>

  <Step>
    ### Wait for the first index

    ctx| reads the default branch and builds the Workspace's index. Settings
    shows the progress. You can start a conversation straight away; answers
    improve once indexing finishes.
  </Step>
</Steps>

A repository can be the workspace repository of only one Workspace in an
organization. Other Workspaces can still add it as a linked repository.

## Root folder

The root folder is the folder in the workspace repository that holds the
Workspace. The default is the repository root.

- ctx| reads knowledge files, `AGENTS.md`, and `.ctxpipe/sources.yaml` only
  below the root folder. Paths in the Files pane, in conversations, and in MCP
  tools are relative to it.
- ctx| writes only below the root folder. This applies to setup commits,
  connector mirrors, source pull requests, ingestion, and conversation
  commits. ctx| refuses a conversation push that changes a file outside the
  root folder, and the agent must undo that change before it can push.
- The root folder is a relative path, such as `docs/context`. It cannot
  start with `/`, contain `..` or `.git`, or use characters other than
  letters, numbers, `.`, `_`, `-`, and `/`.

When you change the root folder in **Settings**, ctx| reads the Workspace
again from the new folder. The current index keeps serving until the new one
is ready. Files in the old folder stay where they are.

## What ctx| adds to the repository

On a writable repository, ctx| makes one setup commit if these files are
missing below the root folder:

- `AGENTS.md` with the Workspace `name` in its front matter and a short folder
  map;
- `.agents/skills/ctxpipe-knowledge/SKILL.md`, which tells coding agents how to
  write knowledge files for this Workspace.

Existing files are kept. ctx| only adds what is missing.

## Workspace settings

Open the **Settings** tab in a Workspace to:

- change the **display name** (stored in `AGENTS.md`) and the **slug** used in
  URLs. Changing the slug breaks old links;
- change the **workspace repository**. The current index keeps serving until
  the new repository is indexed;
- change the [root folder](#root-folder) of the Workspace in its repository;
- add and remove [linked repositories](/docs/workspaces/linked-repositories);
- see whether the Workspace is writable and whether its index is ready;
- delete the Workspace. Deleting removes the Workspace, its conversations, and
  its index from ctx|. The git repository is not deleted.
