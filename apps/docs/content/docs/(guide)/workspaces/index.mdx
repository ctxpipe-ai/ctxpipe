---
title: Workspaces
description: A Workspace is a git repository of team knowledge, plus the code repositories that it searches.
---

A **Workspace** holds one body of team knowledge, for example one product area
or one team. Each Workspace has:

- one **Workspace repository**: a git repository of Markdown knowledge files,
  connector content, and `AGENTS.md`;
- zero or more **linked repositories**: code repositories that ctxpipe indexes,
  so that chat and agents can search them.

An organization can have many Workspaces. Each member of the organization can
open each Workspace.

## Git is the source of truth

All that ctxpipe knows about a Workspace is in files in its Workspace
repository. ctxpipe reads those files to build its search index and knowledge
graph, and writes new knowledge back as ordinary commits. Thus:

- you read, review, and edit the knowledge with the tools that you already use;
- each change that ctxpipe makes is a commit in the history of the repository;
- if you stop using ctxpipe, the repository and its knowledge stay with you.

### What ctxpipe writes

ctxpipe writes only to the Workspace repository, through the ctxpipe GitHub
App. Each change is a small commit to the default branch, or a pull request:

| Change | How it gets to the default branch |
| --- | --- |
| The [setup commit](/docs/workspaces/create-workspace#what-ctxpipe-adds-to-the-repository) of a new Workspace | A commit |
| Connector mirrors: Linear, Notion, Confluence, Slack, PagerDuty, Buildkite, Plain, and the issues and closed pull requests of linked GitHub repositories | A commit for each sync |
| [Knowledge extracted](/docs/workspaces/indexing#how-extraction-works) from linked repositories | One commit for each run, `Update extracted knowledge` |
| Upkeep, for example links that ctxpipe rewrites after a rename, a missing `valid_from`, or the automatic-upgrades setting | A commit |
| A change to `sources/`: add, edit, rename, or remove a source | A pull request that a person merges |
| A [format upgrade](/docs/workspaces/settings#upgrades) | A pull request on `ctxpipe/upgrade/format-<N>` |
| [Workspace chat](/docs/workspaces/chat#publish-with-a-pull-request) | A branch for each conversation, and a pull request that you open |

ctxpipe never force-pushes the default branch. It force-pushes only its own
branches: the branch of a conversation and the upgrade branch. If someone else
pushed to the default branch first, ctxpipe rebases its change onto theirs. If both changed the same lines, ctxpipe merges the two
changes before it pushes.

If the default branch is protected, **Settings** shows **Changes by pull
request**. Conversations and source changes continue through pull requests,
but ctxpipe cannot push commits. Connector mirrors and extracted knowledge
stop until the GitHub App can push to the default branch.

### Code repositories stay read-only

ctxpipe does not write to
[linked repositories](/docs/workspaces/linked-repositories). It reads them with
short-lived tokens that can only read. The GitHub mirror only reads issues and
pull requests, and writes them to the Workspace repository.

A linked repository can also be the Workspace repository of another Workspace
in your organization. ctxpipe then writes to it only for that other Workspace,
and does not extract knowledge from it.

## Use a Workspace

Open a Workspace from the sidebar. The main column is the conversation. The
pane on the right has these tabs:

| Tab | What it shows |
| --- | --- |
| **Files** | The Workspace repository, as the current conversation sees it. Browse, edit, create, rename, and delete files. |
| **Diff** | The changes of the current conversation. It shows only when a conversation is open. |
| **Graph** | The knowledge graph of the Workspace. While ctxpipe builds it, the tab shows **Graph, building**. |
| **Settings** | The name, repositories, sources, ingestion progress, and upgrades. See [Workspace settings](/docs/workspaces/settings). |

The sidebar lists your Workspaces with their five most recent conversations. A
pulse next to a Workspace shows that ctxpipe is ingesting content for it. Home
shows the recent activity and commits of all Workspaces. Choose **Search** in
the sidebar to find a Workspace or a page.

## How a Workspace stays current

When a new commit gets to the default branch, from ctxpipe or from a person,
ctxpipe indexes it. See
[How indexing works](/docs/workspaces/indexing).

## Read-only Workspaces

ctxpipe writes to the Workspace repository only through the ctxpipe GitHub App.
If it cannot push, the Workspace is **read-only**. For example, the repository
is not on GitHub, or the App lost access. Search, chat, and the graph continue
to work on the latest commit, and writes start again when access returns.
**Settings** shows the reason. See
[Write access](/docs/workspaces/settings#write-access).
