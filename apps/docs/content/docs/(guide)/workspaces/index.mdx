---
title: Workspaces
description: A Workspace is a git repository of team knowledge, plus the code repositories that it searches.
---

A **Workspace** holds one body of team knowledge, for example one product area
or one team. Each Workspace has:

- one **Workspace repository**: a git repository of Markdown knowledge files,
  connector content, and `AGENTS.md`;
- zero or more **linked repositories**: code repositories that ctxpipe indexes,
  so that chat and agents can search them.

An organization can have many Workspaces. Each member of the organization can
open each Workspace.

## Git is the source of truth

All that ctxpipe knows about a Workspace is in files in its Workspace
repository. ctxpipe reads those files to build its search index and knowledge
graph, and writes new knowledge back as ordinary commits. Thus:

- you read, review, and edit the knowledge with the tools that you already use;
- each change that ctxpipe makes is a commit in the history of the repository;
- if you stop using ctxpipe, the repository and its knowledge stay with you.

## Use a Workspace

Open a Workspace from the sidebar. The main column is the conversation. The
pane on the right has these tabs:

| Tab | What it shows |
| --- | --- |
| **Files** | The Workspace repository, as the current conversation sees it. Browse, edit, create, rename, and delete files. |
| **Diff** | The changes of the current conversation. It shows only when a conversation is open. |
| **Graph** | The knowledge graph of the Workspace. While ctxpipe builds it, the tab shows **Graph, building**. |
| **Settings** | The name, repositories, sources, ingestion progress, and upgrades. See [Workspace settings](/docs/workspaces/settings). |

The sidebar lists your Workspaces with their five most recent conversations. A
pulse next to a Workspace shows that ctxpipe is ingesting content for it. Home
shows the recent activity and commits of all Workspaces. Choose **Search** in
the sidebar to find a Workspace or a page.

## How a Workspace stays current

Files change in git: someone pushes, a connector mirrors new content, or
ctxpipe commits knowledge that it extracted from a linked repository. ctxpipe
then indexes the new commit. See [How indexing works](/docs/workspaces/indexing).

## Read-only Workspaces

ctxpipe writes to the Workspace repository only through the ctxpipe GitHub App.
If it cannot push, the Workspace is **read-only**. For example, the repository
is not on GitHub, or the App lost access. Search, chat, and the graph continue
to work on the latest commit, and writes start again when access returns.
**Settings** shows the reason. See
[Write access](/docs/workspaces/settings#write-access).
