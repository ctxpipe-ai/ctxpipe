ctx| is an organization-scoped context layer for engineering teams. It connects
the sources your team trusts, prepares them for search and technical reasoning,
and gives AI agents one place to ask before they make a decision.

## Start with one useful path

You do not need to connect everything on day one. The shortest path to value is:

1. Connect GitHub and index one representative repository.
2. Ask a real architecture question in Chat.
3. Install ctx| MCP in one coding agent.
4. Add a context repository when you are ready to bring in Linear, Notion,
   Confluence, or selected Slack threads.

The [hosted quickstart](/docs/getting-started/quickstart) walks through that
path end to end.

## What ctx| gives you

- **Fast repository discovery** across the code your organization has indexed.
- **A knowledge graph** of systems, APIs, libraries, standards, and their
  relationships.
- **Reviewable working context** from source connectors that write to Git.
- **One remote MCP** for Cursor, Claude Code, Codex, OpenCode, and compatible
  clients.
- **A human-facing Chat** for the same organization context.

## Honest limits

ctx| improves an agent's starting point; it does not make model output
authoritative. Graph claims are extracted from connected sources and may be
incomplete or stale. For risky changes, ask for source paths and verify the
answer in code. ctx| complements code review and engineering judgement; it does
not replace either.

Connections are also deliberate. ctx| does not scan a developer laptop or
silently mirror every SaaS workspace. Your team chooses the repositories,
source scope, and Git access boundary.
