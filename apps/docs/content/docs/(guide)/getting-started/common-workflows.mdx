title: Common workflows
description: Where a shared, git-backed Workspace helps engineers and their agents.
---

ctx| helps when a person or an agent needs context beyond the files already
open in front of them.

## Work across repositories

Link the repositories a team owns to its Workspace. Workspace chat and
`ctx_advisor` can then find relevant code across all of them, and the
knowledge graph shows how services, APIs, and libraries relate before anyone
plans a change.

## Apply team instructions

Keep `AGENTS.md`, skills, ADRs, and contribution guides in linked repositories
or in the workspace repository. ctx| retrieves them alongside the code they
govern, so agents follow the same guidance as your engineers.

## Bring product context into git

Linear, Notion, Confluence, and PagerDuty mirror the scope you approve into the
Workspace, and Slack captures specific threads on request. The result is
reviewable Markdown with a git history, not a hidden index.

## Write knowledge down as you go

Ask Workspace chat to turn what it found into a knowledge file, review the
diff, and open a pull request. The next person, and the next agent, starts
from that file.

## Share context across agent clients

Use one MCP endpoint for every compatible client instead of building retrieval
for each agent. People and agents read the same Workspace.

## Run ctx| on your own infrastructure

Self-hosted deployments run the backend, worker, UI, codesearch, Postgres,
graph database, and chat sandboxes on infrastructure you control. See
[Self hosting](/docs/self-hosting).
