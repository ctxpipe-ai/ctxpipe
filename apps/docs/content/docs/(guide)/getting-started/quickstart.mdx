title: Hosted quickstart

Use this guide to set up hosted ctx| with one Workspace and make it available
to an AI coding agent.

## Before you start

You need:

- permission to install or request the ctx| GitHub App on your GitHub account
  or organization;
- a GitHub repository for the Workspace's knowledge. An empty repository is
  fine, and you can create one during setup;
- optionally, code repositories to link;
- Cursor, Claude Code, Codex, OpenCode, or VS Code/Copilot with MCP support.

<Callout type="info" title="Self-hosting?">
  This page covers the hosted product. Start with the
  [self-hosting quickstart](/docs/self-hosting/quickstart) if your team runs
  its own deployment.
</Callout>

## 1. Sign up and connect GitHub

<Steps>
  <Step>
    ### Create your organization

    Sign up at [app.ctxpipe.ai](https://app.ctxpipe.ai). Onboarding opens
    with a welcome that shows how ctx| works. Select **Next**, then create an
    organization. If you sign up with a work email, ctx| suggests an
    organization name from the email domain. You can change it.

    If a teammate invited you, you join their organization. Onboarding then
    shows only the welcome. Select **Get started** to open Home.
  </Step>

  <Step>
    ### Install the GitHub App

    After you create the organization, Home opens. The **Get started** guide
    on Home shows the next steps: connect GitHub, create a Workspace, link
    code repositories, ask a first question, connect a tool, and invite your
    team.

    Select **Connect GitHub**. A window opens. If your ctx| user has no
    linked GitHub account, the window asks you to sign in to GitHub first.
    ctx| needs a GitHub account that can see the installation. Then install
    or authorize the ctx| GitHub App for the account or organization that
    owns your repositories. Give it access to the repository you want
    to use for knowledge, and to any code repositories you want to link.

    A GitHub account can belong to one ctx| user only. If your GitHub
    account belongs to another ctx| user, sign in as that user and unlink
    GitHub (**User account → OAuth Providers → Unlink OAuth**), or use a
    different GitHub account.
  </Step>
</Steps>

ctx| marks a step of the guide done when it sees the result. A member who
joins an organization sees only the steps that apply to members. You can
collapse or dismiss the guide. Until you create a Workspace, Home also shows
the activity of your organization, empty.

The guide shows for 14 days after you finish onboarding, for 14 days after
an organization is created, and in any organization that has no Workspace.
For those 14 days, ctx| opens Home when you open the app.

## 2. Create a Workspace

From the **Get started** guide on Home, select **Create Workspace**. Then
pick the workspace repository:

- **Select GitHub** to use an existing repository;
- **Create on GitHub** to create a new one, then select it;
- **Paste URL** for any other git URL (read-only).

ctx| adds `AGENTS.md` and a knowledge skill if they are missing and starts
to build the Workspace. Then add code repositories and tools. This step is
optional. Select **Done** to go back to Home. The guide shows the build in
two steps: ctx| reads the Workspace repository, then loads the files. You
can ask questions while it loads the files. See
[Create a Workspace](/docs/workspaces/create-workspace).

## 3. Link code repositories

Link code repositories in step 2 of Add Workspace. To link more later, open
**Settings** in the Workspace, then **Add repositories** under **Sources**. Each repository moves from **Pending** to **Indexing** to
**Indexed**. See [Linked repositories](/docs/workspaces/linked-repositories).

## 4. Ask in Workspace chat

Type a question in the Workspace and ask for the files behind the answer:

```text
What are the main services here, and which files support that answer?
```

```text
Before changing authentication, which decisions and standards should an engineer read?
```

A useful answer names relevant files and separates facts from
recommendations. See [Workspace chat](/docs/workspaces/chat).

## 5. Install ctx| MCP

Onboarding does not set up MCP. Under **More**, the **Get started** guide
links to [Remote MCP](/docs/mcp/mcp-docs). To set up your own machine, run
this from a repository:

```bash
npx ctxpipe init
```

The installer signs you in, asks which organization and clients to configure,
and writes configuration for the repository, your user profile, or both. Your
MCP client asks you to authorize ctx| the first time it connects.

Then give the agent a concrete task:

```text
Use ctxpipe before planning this change. Search the knowledge for the
relevant standards and decisions, search the code for the source areas, and
say what still needs checking in code.
```

See [Remote MCP](/docs/mcp/mcp-docs) for team setup, non-interactive flags,
and manual configuration.

## 6. Connect more sources

From **Connectors**, add the tools whose content should live in the Workspace:

- **Linear, Notion, Confluence, and PagerDuty** need a connection and a source.
  After you connect the tool, open its Workspaces step (**Add to Workspaces**,
  or **Choose Workspaces** for Linear). ctx| opens a pull
  request that adds the source file. After you merge it, ctx| mirrors the
  selected content into the Workspace.
- **Slack** captures an existing thread when someone mentions the ctx| bot in
  it.

See [Connections](/docs/connections).

## Setup is complete when

- the Workspace's index is ready and its linked repositories are indexed;
- Workspace chat answers a question and cites useful files;
- your MCP client can call `list_workspaces` and `search_knowledge`.
