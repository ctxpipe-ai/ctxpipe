---
title: How ctx| works
description: How knowledge moves from your sources into a Workspace and out to people and agents.
---

ctx| sits between your team's sources and the people and agents who need to
understand them. It keeps that knowledge as files in git, keeps the files
current, and builds an index so questions get grounded answers quickly.

## Flow

<Steps>
  <Step>
    ### Knowledge lives in a workspace repository

    Each [Workspace](/docs/workspaces) has one git repository of Markdown
    knowledge. You and your agents write to it like any other repository. Its
    files and their links and claims are the source of truth.
  </Step>

  <Step>
    ### ctx| keeps it current

    ctx| commits to the workspace repository on your behalf:

    - [connectors](/docs/connections) mirror the Linear, Notion, Confluence,
      PagerDuty, and GitHub content you selected, and capture Slack threads
      when someone mentions the bot;
    - [linked repositories](/docs/workspaces/linked-repositories) are indexed,
      and the services, APIs, and libraries found in them are written back as
      knowledge files.

    Each change is a small commit to the default branch with a clear message.
  </Step>

  <Step>
    ### ctx| indexes every new commit

    When the default branch changes, ctx| reads the files and rebuilds the
    Workspace's search index and knowledge graph. Reading never changes your
    files, and the previous index keeps serving until the new one is ready.
  </Step>

  <Step>
    ### People and agents ask

    [Workspace chat](/docs/workspaces/chat) answers from the Workspace's
    knowledge, graph, and linked code, and can propose changes as a pull
    request. Coding agents reach the same context through
    [MCP](/docs/mcp/mcp-docs).
  </Step>
</Steps>

## Verify consequential answers

Answers combine retrieved files, graph claims, and code search. For
consequential work, ask for the files behind an answer and check the current
code before changing behavior.

<Callout title="Self-hosting">
  Self-hosted deployments use the same model with your own backend, UI,
  worker, codesearch, Postgres, graph database, and chat sandboxes. See the
  [self-hosting section](/docs/self-hosting).
</Callout>
