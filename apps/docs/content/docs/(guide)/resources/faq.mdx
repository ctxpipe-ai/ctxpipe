## Product

### What is ctxpipe in one sentence?

An organization-scoped context platform for engineering agents: it ingests the
sources you select, builds searchable and graph context, and exposes it through
**MCP** read tools.

### Is ctxpipe only for GitHub?

No. ctxpipe also reads Confluence, Linear, Notion, Slack, and PagerDuty. For code,
the best-supported path is the **GitHub App**. GitLab and other git hosts have no
first-party setup flow.

ctxpipe can read a repository on another git host as a plain git source. Plain git
sources are read-only. ctxpipe reads them with git over HTTPS or, on self-host, HTTP, and with no credential,
so a private repository on another host does not work. The URL rules depend on
where ctxpipe runs:

- **Hosted ctxpipe, and a deployment where `SANDBOX_PROVIDER` is not `docker`:**
  the URL uses `https://` and the default port. The host is a public domain
  name. ctxpipe refuses an IP address, a private name such as `localhost`, and a
  host that resolves to a private address.
- **Self-hosted ctxpipe with `SANDBOX_PROVIDER=docker`:** the Compose file and the
  AWS CDK stack set this value. On another setup, the operator sets it
  explicitly. The URL can also use `http://`, a custom port, an IP address, or a
  private host name. Agent Vault reaches a private address only when that
  address is in `AGENT_VAULT_NETWORK_ALLOWLIST`.
- **Both:** SSH (`git@…` or `ssh://`), `git://`, and `file://` URLs are not
  supported. ctxpipe always refuses cloud metadata addresses (169.254.0.0/16 and
  the IPv6 metadata addresses). The URL has no user name, password, query, or
  fragment. ctxpipe does not follow a redirect.

See [Plain git repositories](/docs/workspaces/linked-repositories#plain-git-repositories).

## MCP

### How does an MCP tool call choose the organization?

The `/mcp` URL is the same for every organization. Each tool call names one
organization with the `org` argument (the slug from your ctxpipe URL). Only
`list_workspaces` can omit it. Then it returns the Workspaces of each
organization in the connection.

ctxpipe is multi-tenant, so the server checks every call. It allows the call only
when the organization is in the set that you chose when you authorized the
client, and you are still a member. Tools have no `orgId` argument for an agent
to spoof. An organization API key reads one organization, and `org` must name it.

The server accepts the old `?orgSlug=` URL parameter and ignores it. You can
leave it in an old client configuration or remove it.

### Streamable HTTP vs SSE?

ctxpipe uses **Streamable HTTP** (MCP 2025-03-26). Legacy SSE-only clients may not
work without updates.

### What do the MCP tools do?

They give your coding agent seven read-only tools: `list_workspaces`,
`search_knowledge`, `search_code`, `find_symbol`, `read_file`, `list_files`, and
`get_related`. The agent does the reasoning. ctxpipe returns facts with refs and
runs no model for each call. See [Use ctxpipe from your agent](/docs/mcp/use-from-your-agent).

## Self-hosting

### What is the supported small-deployment path?

Use `pnpm start` (the Compose **`deploy`** profile) for an evaluation or small
internal deployment. It is not the contributor development stack. See
[Self-hosting](/docs/self-hosting) for Docker, Terraform, and AWS options.

### Which Postgres version?

The reference stack uses **Postgres 17** (pgvector image in `docker-compose.yml`).

### Where do I configure the graph database?

Configure `GRAPH_DB_URI` and `GRAPH_DB_PROVIDER` in your deployment
environment.

## Account & org

### How do invites work?

Email invitations from **Settings → Members**; accepting binds the user with the
invited role. Details: [Team members](/docs/managing-organization/team-members).

### Can I verify my company domain?

Not in the current product. Organization access is based on explicit
invitations and roles.
