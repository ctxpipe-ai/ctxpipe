# ADR-038: Self-hosted ClickStack + Langfuse (ops observability)

**Status:** Accepted | **Date:** 2026-09-21 | **Updated:** 2026-09-25 | **Tags:** observability, railway, clickhouse, langfuse, hyperdx, otel

### Context

Hosted observability was Langfuse Cloud (paid) plus unused Better Stack / Amplitude free-tier. Product Railway `ctxpipe` clones every service into ~15 `pr-*` environments, so putting ClickHouse in that project would copy volumes and still could not share private DNS across environments. Amplitude had no funnels; we only needed page views and APM.

### Decision

1. **Separate Railway project** `ctxpipe-observability` (`has_pr_deploys = false`, region **`us-east4-eqdc4a`** — same Virginia metal as product Railway and Neon `aws-us-east-1`, [ADR-029](ADR-029-railway-us-east-next-to-neon.md)). Internal ops tool in the OSS repo under [`ops/observability/`](../../../ops/observability/), not [`infra/module/ctxpipe`](../../../infra/module/ctxpipe) and not [`.github/workflows/deploy.yaml`](../../../.github/workflows/deploy.yaml). Terraform documents `var.railway_regions` and `lifecycle.ignore_changes = [regions]` for the same provider bug as product. After create or apply, pin with [`scripts/railway-set-regions.sh`](../../../scripts/railway-set-regions.sh) (`RAILWAY_SERVICE_SET=observability`, `RAILWAY_PROJECT_ID=305aa114-c6f3-4aca-b883-0faa9c331aa2`). Railway MCP `create-service` has no region field and uses the workspace preferred region (Singapore); do not treat a successful apply as proof of Virginia. Volumes follow the service — `clickhouse-data` is a 50GB copy with downtime.

2. **One small ClickHouse** (1 GiB cap, volume) with databases `otel` (ClickStack) and `langfuse`. Hot tier is the volume (3-day TTL move for `otel`). Cold tier is Railway bucket `clickhouse-cold`. `otel` delete TTL is 13 months. Langfuse is not deleted by tiering. `query_log` and `error_log` stay local, TTL 3 days. Detail: decision 12. Langfuse Postgres is a **dedicated `langfuse` database** on the existing Neon `ctxpipe` project (same compute; not a new Neon project). A schema on `neondb` is rejected — Langfuse Prisma migrations hardcode `public`. Blobs on Railway bucket `langfuse-events`. No replicas, no MinIO, no Railway Postgres. Node tuning is decision 9.

3. **One ingest collector:** ClickStack (`clickhouse/clickstack-otel-collector`) with `CUSTOM_OTELCOL_CONFIG_FILE` adding `filter/llm_only` + `otlphttp/langfuse` (`x-langfuse-ingestion-version: "4"`). Apps still export OTLP once ([ADR-011](ADR-011-backend-observability-otel.md)). The product `otelcollector` service remains until cutover, then is removed. Fallback: contrib collector only — never two collectors. The pinned image has `prometheus` and no `redis` receiver (decision 8).

4. **Prod + PR** send traces, logs, metrics, and LLM spans to the **public** collector (token header) when `OTEL_EXPORTER_OTLP_*` is set. Resource attr `deployment.environment` = `production` | `pr-N` (`RAILWAY_ENVIRONMENT_NAME`). Langfuse tags `env:production` / `env:pr-N`. PR deploy writes the endpoints from `OBSERVABILITY_OTLP_ENDPOINT` / `OBSERVABILITY_OTLP_HEADERS`. Product Terraform `otel_otlp_endpoint` / `otel_otlp_headers` stay optional until cutover; empty still uses the in-project `otelcollector`. A 6-hour read of `otel.otel_traces` on 2026-09-25 showed `pr-343` and `observability` only, no `production` rows.

5. **PR metrics** use `FlushOnDemandMetricReader` (no 60s timer) + `forceFlushOtel()` after Hono requests and OpenWorkflow `withLogger` jobs. The flush exports collected scope metrics even when one observable callback throws. Production keeps `PeriodicExportingMetricReader` at 60s. Detail: [ADR-011](ADR-011-backend-observability-otel.md).

6. **Browser:** `@hyperdx/browser` with `url` = same-origin `/.otel` (UI proxies `POST` to `/.otel/v1/traces`, `/v1/logs`, `/v1/metrics`). The proxy drops query, fragment, and userinfo, then rewrites credential path segments to `{token}` and `{invitation}`, before forward ([ADR-011](ADR-011-backend-observability-otel.md)). `disableReplay: true`. `consoleCapture: true`. SPA `page_view` via `HyperDX.addAction`. Global attributes `userId`, `teamId` (org id), `teamName` (org slug). Ids only. [ADR-017](ADR-017-amplitude-analytics.md) is superseded. Session rows and console logs do not land where the SDK names suggest (decision 11). React Query failures that happen before session identity is known are buffered, then flushed with the identity (ADR-011).

7. **Deploy path:** Terraform in [`ops/observability/terraform/`](../../../ops/observability/terraform/) targets the existing Railway project `305aa114-c6f3-4aca-b883-0faa9c331aa2` (does not create it). ClickHouse, the collector, and `railway-telemetry` use the **Railway GitHub integration** (`source_repo` + `root_directory`). The Railway GitHub App is not installed on `ctxpipe-ai/ctxpipe` (`NO_INSTALLATION`), so a push does not rebuild them. After apply on `main`, the workflow calls `serviceInstanceDeployV2` for each of those services whose `ops/observability/<name>/**` changed (all three when `github.event.before` is missing or all zeros, or on `workflow_dispatch` input `deploy_services`, default `all`). That restarts the service and does not copy the ClickHouse volume. Installing the GitHub App would make pushes rebuild natively instead. HyperDX dashboard provisioning stays manual (`ops/observability/hyperdx/provision.ts`); it needs a personal access key. Image services pull public images. No static `OBSERVABILITY_RAILWAY_TOKEN`. [`.github/workflows/observability.yaml`](../../../.github/workflows/observability.yaml) validates Terraform on changes under `ops/observability/**`. A same-repo pull request also runs `terraform plan` in GitHub Environment `terraform-plan` (that environment currently has no protection rules), posts `## Observability Terraform Plan`, and never applies. `TF_VAR_github_repo_branch` is `main` on the plan and on apply, so the plan is the post-merge preview. Apply runs only when `github.ref` is `refs/heads/main` (push or `workflow_dispatch`). It runs `terraform init` for the R2 backend key `observability/terraform.tfstate`, pins `us-east4-eqdc4a` (`RAILWAY_SERVICE_SET=observability RAILWAY_PROJECT_ID=305aa114-c6f3-4aca-b883-0faa9c331aa2 bash scripts/railway-set-regions.sh`), plans, and applies in GitHub Environment `observability`. **Create that environment with required reviewers and a main-only deployment branch policy before merge.** If it is missing, the first push creates it with no rules and apply is ungated. Concurrency group `observability-apply` does not cancel an in-progress apply. The apply refuses a plan that would delete or replace any `railway_service`, `railway_custom_domain`, or `railway_variable_collection`, or change a service volume, so ClickHouse and Mongo volumes and the public hostnames are not recreated. [`imports.tf`](../../../ops/observability/terraform/imports.tf) adopts the API-created services, variable collections, custom domains, and service domains (import blocks are no-ops once that address is in state). The first PR plan must be imports plus in-place updates; review it before merge. Railway holds secret values. Terraform holds wiring and does not list those secret names, so a variable_collection update cannot delete them (it deletes a name only when it is in state and absent from config). Owners: clickhouse `CLICKHOUSE_OTEL_PASSWORD` and `CLICKHOUSE_LANGFUSE_PASSWORD`; collector `HYPERDX_API_KEY` and `LANGFUSE_AUTH_STRING`; langfuse-web `DATABASE_URL`, `DIRECT_URL`, `NEXTAUTH_SECRET`, `SALT`, `ENCRYPTION_KEY`, `LANGFUSE_INIT_PROJECT_PUBLIC_KEY`, `LANGFUSE_INIT_PROJECT_SECRET_KEY`, `LANGFUSE_INIT_USER_PASSWORD`, and `LANGFUSE_INIT_USER_EMAIL` (put `connection_limit=1&keepalives=0` on the URLs; the worker references those variables); railway-telemetry `RAILWAY_API_TOKEN`. Consumers use Railway references (`${{clickhouse.CLICKHOUSE_*_PASSWORD}}`, `${{collector.HYPERDX_API_KEY}}`, `${{langfuse-web.DATABASE_URL}}` / `DIRECT_URL` / `SALT` / `ENCRYPTION_KEY`, and `authorization=${{collector.HYPERDX_API_KEY}}`). The workflow needs only existing `RAILWAY_TOKEN`, `R2_ACCESS_KEY_ID`, and `R2_SECRET_ACCESS_KEY`. A fresh project sets the Railway secrets once; Terraform does not copy them into GitHub. langfuse-web `NODE_OPTIONS` is also omitted from the import id so it stays. Volumes are read as part of `railway_service` import (project default environment), not a separate resource. A missed volume read would create a second volume without deleting the service; the apply guard rejects that plan. Service domain subdomains are the live host labels, so apply does not rename `*.up.railway.app`. Public collector hostname is `telemetry.ctxpipe.ai`. Public HyperDX dashboard hostname is `hyperdx.ctxpipe.ai`. Public Langfuse hostname is `langfuse.ctxpipe.ai`. `LANGFUSE_INIT_*` pre-creates the Langfuse project + API keys so the collector can fan out on first boot. `RAILWAY_API_TOKEN` is a Railway variable on `railway-telemetry` (not a Terraform variable) and is the workspace token for that cron. **`DEFAULT_CONNECTIONS` / `DEFAULT_SOURCES` seed a new team that has none; they do not update an existing team.** **Superseded:** HyperDX `OTEL_SDK_DISABLED` (that blocked all export, including to this collector). HyperDX now sends traces and logs to the private collector. `OTEL_METRICS_EXPORTER=none` and `RUN_SCHEDULED_TASKS_EXTERNALLY=true` stay, so there is no metric timer and the in-process alert cron stays off. `HDX_EXPORTER_ENABLED=false` keeps the ingest key out of `/api/config`. **Awake:** `collector`, `clickhouse` (production 60s metrics), `langfuse-worker` (stock always-on Redis consumer), `redis` (stays up while that worker runs). **`railway-telemetry`** is a cron (`*/5 * * * *` in Terraform `cron_schedule` and in `railway.toml`, `restartPolicyType = NEVER` in `railway.toml`); it starts, exports, and exits. **Sleeps:** HyperDX (observed 2026-09-25 06:58–08:32Z and after 09:16Z). **Serverless on, stays up:** Mongo and Langfuse web. `sleepApplication` stays true on all three. Nothing on those three exports on a timer, and nothing polls them. Sleep means deployment `SLEEPING` and missing `railway.cpu` / `railway.memory` samples, not zeros. Langfuse web stays up because the stock `langfuse/langfuse:3` image keeps a Prisma TCP keepalive to Neon (`:5432`, about every 10s) and ioredis `keepAlive: 10000` on 4–5 Redis sockets (v3.225.11). No `LANGFUSE_*` switch disables them. A cold-start 502 is covered by the collector `otlphttp` retry. The upstream fix is ioredis keepalive off and an idle Prisma pool. Mongo stayed Online with zero packets for ~90 minutes (06:58–08:32Z and 09:16–09:29Z); the cause is Railway. Treat it as always on (~0.025 core, ~270 MB). The 50 GB volume is billed either way. HyperDX `MONGO_URI` sets `heartbeatFrequencyMS=1200000`; the live driver still heartbeats every 10s, and only while HyperDX is awake. A temporary `ops-probe` service is live in the project and is **not** part of this stack; it is not in Terraform and will be deleted.

8. **Signal sources** (all into the one collector, then ClickHouse; LLM spans also fan out):

   - **App OTLP** from backend, openworkflow, and codesearch (decision 4), plus the browser (decision 6).
   - **Collector + ClickHouse Prometheus.** `prometheus/self` scrapes `127.0.0.1:8888` (job `otel-collector`; `target_info` dropped so `service.name` stays `otel-collector`) and `clickhouse.railway.internal:9363` every 60s. ClickHouse `/metrics` is keep-listed to the Observability Stack names plus a small health set. `resource/self` sets `deployment.environment=observability` and `service.namespace=ctxpipe`. Pipeline `metrics/self` uses the base `clickhouse` exporter.
   - **HyperDX and Langfuse self-traces.** Private `collector.railway.internal:4318` with the ingest token. HyperDX: traces and logs, batch export only when a queue is non-empty. Langfuse web and worker: traces only. Web sampling is `OTEL_TRACE_SAMPLING_RATIO=1`. The worker has no `OTEL_TRACES_SAMPLER`. `ClickhouseWriter` opens a `write-to-clickhouse` span on every tick inside one long-lived trace, so a ratio sampler cannot thin it. Terraform sets `LANGFUSE_INGESTION_CLICKHOUSE_WRITE_INTERVAL_MS=20000` (3 spans/min from that loop; a full batch of 1000 rows still flushes immediately; a partial batch can wait 20s), `LANGFUSE_QUEUE_METRICS_ENABLED=false`, `LANGFUSE_MONITOR_SCHEDULER_ENABLED=false` (Langfuse Monitors off; the runner is hardcoded to 30s with no interval env), and `LANGFUSE_TRACE_DELETE_BATCH_ACTION_RUNNER_INTERVAL_MS=120000` (trace deletes can lag 120s). Idle is about 2 spans/min until the first ingestion opens the writer, then about 5/min. Those four names are set on the live worker. `OTEL_METRICS_EXPORTER=none` and `OTEL_LOGS_EXPORTER=none` on web and worker.
   - **`railway-telemetry` cron** ([`ops/observability/railway-telemetry/`](../../../ops/observability/railway-telemetry/)). Each run covers the fixed 5-minute window ending at the last 5-minute boundary, sampled every 60s, points in `[start, end)`. Railway GraphQL `metrics` for observability `production`, product `production`, and product `pr-*`: gauges `railway.cpu.usage`, `railway.cpu.limit` (cores), `railway.memory.usage`, `railway.memory.limit`, `railway.network.rx`, `railway.network.tx`, `railway.disk.usage` (bytes). Network rx/tx is the bytes in that 60s sample, not a cumulative counter. Resource attrs: `service.name` (Railway service name), `deployment.environment` (`observability` or the Railway env name), `railway.project`, `railway.project.id`, `railway.service.id`, `railway.environment.id`, `railway.region` when present. Observability `environmentLogs` for the same window (runtime stdout, cap 5000 lines; build logs are not requested; lines for service `railway-telemetry` are skipped). Product project logs are not collected. Redis `INFO` on `REDIS_URL` because the collector image has no redis receiver: gauges for memory, clients, uptime, and `redis.db.keys`; monotonic sums for commands, keyspace hits/misses, and connections received. The Railway API read does not start a service. Missing `RAILWAY_API_TOKEN` still exports Redis and a WARN self-log, then exits 1.

9. **ClickHouse 1 GiB node.** `max_server_memory_usage` is 1 GiB. Default caches are multi-GiB (mark cache 5 GiB, uncompressed cache 8 GiB, text-index caches 1–2 GiB). `asynchronous_metric_log` reached billions of rows and merge memory past the cap (`MEMORY_LIMIT_EXCEEDED` on 2026-09-25). `remove="1"` stops those loggers (`asynchronous_metric_log`, `metric_log`, `trace_log`, `text_log`, `part_log`, `query_thread_log`, and the other system logs in [`system_logs.xml`](../../../ops/observability/clickhouse/config.d/system_logs.xml)). `remove="1"` does not rewrite tables already on the volume. HyperDX's built-in ClickHouse page reads `system.metric_log`; that logger is removed on purpose, and the Observability Stack dashboard replaces those charts. `query_log` stays for that page's Query Log tab, with a 3-day TTL, and `error_log` has the same TTL. `crash_log` is not removed. Cache caps in [`caches.xml`](../../../ops/observability/clickhouse/config.d/caches.xml) are all under 1 GiB (`uncompressed_cache_size` 0). The Prometheus keep-list exists because inserting the full `:9363` scrape every 60s also OOM'd this node (a local scrape was 3265 samples before relabel, 42 after).

Sources, cross-linked by name: Logs (`otel.otel_logs`), Traces (`otel.otel_traces`), Metrics (`otel_metrics_gauge` / `histogram` / `sum` / `summary` / `exponential_histogram`), Sessions (`otel.hyperdx_sessions`). 11. **Known limits** (checked in code and against ClickHouse on 2026-09-25):

    - **`hyperdx_sessions` is empty** (live `count()` was 0). ClickStack routes a log into that table only when `rr-web.event` is set. `@hyperdx/browser` starts the rrweb recorder only when `disableReplay` is not true. Replay stays off. `rum.sessionId` on spans does not insert session rows.
    - **`consoleCapture` emits spans**, not `otel_logs`. The SDK writes spans named `console.log` / `info` / `warn` / `debug` on the trace pipeline. The logs URL is passed to the session recorder, which does not start. `otel_logs` for `service.name=ui` stayed 0 in the browser proof window.
    - **Bun backend lacks GC metrics.** Bun does not emit `gc` PerformanceObserver entries, so `v8js.gc.duration` stays empty, and `v8.getHeapSpaceStatistics` throws. Process gauges `v8js.memory.heap.used` and `v8js.memory.heap.limit` come from `v8.getHeapStatistics`. Codesearch on Bun is the same. Openworkflow on Node still records per-space heap and GC through `@opentelemetry/instrumentation-runtime-node`.
    - **HyperDX charts every OTLP Sum as a counter** (`greatest(Value - previous, 0)` per bucket), including non-monotonic sums. Current levels (Redis clients, uptime, Railway CPU and memory, network bytes in a sample) are gauges. Only true cumulative counters stay monotonic sums.
    - **Worker idle traces are the runner intervals** in decision 8 (~2/min, then ~5/min). Live `otel_traces` on 2026-09-25 10:15–10:26Z alternated 3 and 7 spans per minute. `LANGFUSE_MONITOR_SCHEDULER_ENABLED=false` turns Langfuse Monitors off.
    - **Pre-session browser query errors are buffered.** React Query and mutation failures that happen before session identity is known wait (cap 20, or 10 seconds) and then record with `ctxpipe.ui.deferred_ms`. See [ADR-011](ADR-011-backend-observability-otel.md).
    - **First Terraform apply restarts ClickHouse two or three times.** In-place service and variable updates each redeploy, and the workflow deploys the changed GitHub-built services again. None of those restarts copies the volume.
    - **A new `otel` table needs a line in `tiering/otel.sql`.** The collector `ttl: 9360h` only sets the delete horizon. The 3-day move to cold is the SQL file. Re-run it after adding the statement.
    - **Cold reads fail while `clickhouse-cold` is down.** Inserts still land on the volume. `count()` over cold parts can be answered from local metadata. Hot reads still work.
    - **Langfuse cost for 2026-09-25 05:00–07:00Z is about 2×.** `pr-343` generations in the 05:00 and 06:00 hours include both `ChatOpenAI` and `chat openai/gpt-5.6-terra` for the same calls (74 and 72 in the 05:00 hour). The 07:00 hour is single-counted (`ChatOpenAI` only). The duplicate rows are still in Langfuse.
    - **HyperDX dashboards are manual.** [`provision.ts`](../../../ops/observability/hyperdx/provision.ts) is an operator shell command. The workflow does not run it.
    - **`ops-probe` is temporary.** It is not in Terraform and will be deleted.

12. **Tiered ClickHouse storage.** Redefine policy `default` (local volume, then cold) instead of adding a named policy. ClickStack and Langfuse create `MergeTree` tables with no `storage_policy`, so they keep the name `default` and inherit cold. A named policy would need `ALTER` on every table, and a Langfuse migration that recreates a table would drop it. `otel` tables in [`tiering/otel.sql`](../../../ops/observability/clickhouse/tiering/otel.sql): move to volume `cold` after 3 days, delete after 13 months. Langfuse is move-only through `move_factor` 0.2 (oldest parts move when free space on the hot filesystem drops below 20%). `query_log` and `error_log` use `local_only` and delete after 3 days (live `system.tables` on 2026-09-25 confirmed both). Object metadata for disk `s3_cold` lives on the volume under `disks/s3_cold/`. A volume backup that omits that directory cannot read the bucket. Railway bucket deletion is restorable for 52 hours, then permanent. There is no object lock or versioning. Bucket outage: cold reads fail, ingest continues. Path-style `${{clickhouse-cold.ENDPOINT}}/${{clickhouse-cold.BUCKET}}/clickhouse/` was proven live 2026-09-25 (a partition move wrote objects; a cache-bypass read issued S3 GetObject). Measured `otel` ingest ~30 MiB/day → about $0.17/mo in the bucket at 13 months, versus about $1.74/mo on the volume. The bucket (region `iad`) is created outside Terraform. ClickHouse variables reference `${{clickhouse-cold.ENDPOINT}}`, `${{clickhouse-cold.BUCKET}}`, `${{clickhouse-cold.ACCESS_KEY_ID}}`, `${{clickhouse-cold.SECRET_ACCESS_KEY}}`, and `${{clickhouse-cold.REGION}}`. Rolled out 2026-09-25 09:52–09:58Z (clickhouse deployment `b9634299`, collector `3aac559e`, commit `4b102acd`; `otel.sql` applied as the `otel` user). Procedure: [`ops/observability/clickhouse/README.md`](../../../ops/observability/clickhouse/README.md).

### Consequences

**Positive**

- One billable APM + LLM stack (~$25–35/mo target) instead of Langfuse Cloud.
- Self-hosters copy `ops/observability` or point `OTEL_EXPORTER_OTLP_*` at any collector.
- PR Serverless can sleep: no periodic metric export, no per-env collector.
- One collector scrape plus one cron covers stack metrics, Railway resource gauges, observability runtime logs, and Redis. Sleepable UIs are not polled.

**Negative / trade-offs**

- Single-node ClickHouse: crash loses ingest until restart. `otel` retention is 13 months, with 3 days on the volume; cold part metadata stays on the volume, so a volume-only backup cannot read the bucket. System `metric_log` is gone; use the Observability Stack dashboard. `query_log` / `error_log` keep 3 days on the local disk.
- Cross-project OTLP is public + token (private networking does not cross Railway projects/environments).
- Apply is [`.github/workflows/observability.yaml`](../../../.github/workflows/observability.yaml) on `main` after a same-repo PR plan. The first plan imports API-created resources; it must be imports plus in-place updates before merge. The first apply restarts ClickHouse two or three times and does not copy the volume. The Railway GitHub App is not installed, so the workflow redeploys changed GitHub-built services; `source_repo_branch` and `TF_VAR_github_repo_branch` are `main`. Two Railway buckets (`langfuse-events`, `clickhouse-cold`) the 0.6.1 provider cannot create stay manual. The workflow adds no GitHub secrets (existing `RAILWAY_TOKEN`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`). GitHub Environment `observability` needs required reviewers and a `main`-only deployment branch policy before merge. `terraform-plan` exists and has no protection rules. DNS for `telemetry.ctxpipe.ai`, `hyperdx.ctxpipe.ai`, and `langfuse.ctxpipe.ai` is operator-owned. The Railway Terraform provider 0.6.1 cannot set Serverless sleep; GitHub-built ingest services set `sleepApplication` in `railway.toml`. The `railway-telemetry` cron is Terraform `cron_schedule = "*/5 * * * *"` and the same value in `railway.toml`. Provider 0.6.1 sends `cronSchedule` on every service update with no `omitempty`, so leaving it unset would clear the live cron. Image-service Serverless is set on the Railway service (HyperDX sleeps; Mongo and Langfuse web stay up). Region on Update is GraphQL, same as product ([ADR-029](ADR-029-railway-us-east-next-to-neon.md)). Workspace preferred region is Singapore; MCP `create-service` has no region argument. The apply job runs `RAILWAY_SERVICE_SET=observability` on [`scripts/railway-set-regions.sh`](../../../scripts/railway-set-regions.sh) before plan. A 50GB `clickhouse-data` region flip copies the volume and takes ClickHouse down.
- Langfuse isolation is a second database on the existing Neon project, not a schema.
- Production 60s metrics keep the collector and ClickHouse awake by design. The Langfuse worker is a stock always-on consumer (cron+timeout stacked overlapping replicas and did not save idle time), so Redis stays up with it. HyperDX sleeps. Mongo and Langfuse web have Serverless on and stay up (decision 7). Product **PR** apps still use `FlushOnDemandMetricReader`. `ops-probe` is drift until it is deleted.
- Browser session search stays empty while replay is off. Console capture is trace spans. Query errors before session identity are buffered (ADR-011). Bun processes have no GC metric. HyperDX will draw a Sum as a rate-of-change even when the number is a level. Worker idle traces are the runner intervals in decision 8 (~5 spans/min once ingestion has started). Langfuse cost dashboards for 2026-09-25 05:00–07:00Z count those generations about twice.

### Alternatives Considered

- **ClickStack inside `ctxpipe`:** Rejected — PR volume clones and no cross-env private DNS.
- **Keep Amplitude:** Rejected — no funnels; `@hyperdx/browser` is OTEL and operator-pointable.
- **Periodic metrics on PR:** Rejected — 60s export prevents Railway sleep.
- **Custom MetricReader in production:** Rejected — always-on prod wants the 60s periodic reader.
- **Dedicated schema on `neondb`:** Rejected — Langfuse Prisma SQL hardcodes `public`; same Neon instance gets database `langfuse` instead.
- **Static `OBSERVABILITY_RAILWAY_TOKEN` + `railway up` Action:** Rejected — ClickHouse/collector deploy via Railway’s GitHub integration; the workspace token already used by `infra/` is enough for manual Terraform apply.
- **`OTEL_SDK_DISABLED` on HyperDX:** Superseded — it also blocked self-traces. Metrics exporter `none` is what keeps the sleep timer off.
- **Redis receiver on the ClickStack collector:** Unavailable in the pinned image. Redis `INFO` runs from `railway-telemetry` instead. A second collector is still rejected.
- **Full ClickHouse `/metrics` scrape:** Rejected — thousands of series, and inserts OOM'd the 1 GiB node.
- **Leave ClickHouse system logs at image defaults:** Rejected — `asynchronous_metric_log` grew past the memory cap.
- **Enable rrweb so `hyperdx_sessions` fills:** Rejected — `disableReplay: true` stays; session rows require `rr-web.event`.
- **Named ClickHouse storage policy:** Rejected — tables created without `storage_policy` would stay on the built-in `default` and skip cold. Redefining `default` is what they inherit.
- **1% trace sampler on the Langfuse worker:** Rejected — `write-to-clickhouse` is one long-lived trace, so a ratio does not thin it. Runner intervals do.
