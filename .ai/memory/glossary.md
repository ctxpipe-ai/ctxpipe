# Project Glossary

## Terms
| Term | Definition |
|------|------------|
| ctxpipe | The monorepo and product name — a code-context platform |
| Workspace | The product unit — a **Context Workspace** in an Organisation, identified by a `ws_` id (own row, not the `repositories` row). One **workspace repository** (portable knowledge + connector mirrors) and zero or more **linked repositories** (codesearch). Display name defaults to the workspace-repository name, is editable, and is **git-canonical** in `AGENTS.md` front matter at that repo root. Cannot exist without a workspace repository. Many per Organisation. Not the git repo itself, not a Linear Project, not the FalkorDB `project()` verb. Formerly called Project (`proj_`). |
| Workspace slug | URL segment for a Workspace, unique per Organisation (normalised lowercase). Default is the GitHub repository name, or the last path segment of any other git URL; collisions get `-2`, `-3`. Stored on the `ws_` row, not in git. Distinct from display name and from `ws_`. Relink does not change it. |
| Workspace repository | The single git remote that *is* the Workspace’s portable source of truth (knowledge + connector mirrors). Any git URL in principle; GitHub has first-class select/create UX. A URL is the workspace repository of at most one Workspace per Organisation. Implicitly included in that Workspace’s codesearch set. Described in `AGENTS.md`; not duplicated as a self-URL under `repositories/` by default. Formerly “backing repository.” |
| Linked repository | A git repository scoped to a Workspace for codesearch, in addition to the workspace repository. May be a URL that another Workspace already uses as its workspace repository. Declared as a markdown file under `repositories/` in the workspace tree (front matter: git URL, branch, …; body: description). Formerly “attached repository.” |
| Unlinked repository | A repository in an Organisation that is neither a workspace repository nor linked to any Workspace. A Workspace cannot exist without a workspace repository; a repo can exist without a Workspace. |
| Job | Background work that **updates the workspace repository**. Many kinds: ingest, connector sync, ops/bootstrap, link/unlink, rename rewrite, claims upgrade, `valid_from` backfill, semantic rebase, UI file edit, … There is no single “the maintenance job.” Distinct from **hydrate**, which refreshes the projection and does not edit git. Bound command/result metadata is in `workspace_write_jobs`; each concern has its own typed OpenWorkflow workflow, which owns execution, retry and resume ([ADR-047](decisions/ADR-047-native-durable-write-workflows.md)). |
| workspace_write_jobs | Org-scoped Postgres ledger for write **jobs** (`wjob_` id): kind, generation, desired SHA, status (including paused), payload, and commit SHA. Used for crash-after-push idempotency, pause/resume when the remote is not writable, per-kind retry caps, and relink CAS. Native OpenWorkflow owns execution and waiting; the tenant-scoped public projection may reconcile its matching owner’s terminal state ([ADR-047](decisions/ADR-047-native-durable-write-workflows.md)). |
| Projection | Derived retrieval state built from a workspace-repository SHA: Postgres knowledge rows, FalkorDB, Zoekt/SCIP, embeddings, and similar indexes. Intent is search/retrieval, not source of truth. If ctxpipe is off, the projection goes away; the Workspace repository remains. |
| Hydrate | Read-only (wrt git) rebuild of the **projection** from a workspace-repository tree. No extract LLM. Never writes the workspace repository. |
| Desired SHA | Stored commit we intend for a remote: workspace repository = tip of the **default branch**; linked repository = tip of front-matter `branch` (or default). Follows the remote tip, including rewind. Not a high-water mark. Always written from a **resolve** of that ref (webhook/push are triggers only — do not persist payload `after`). Distinct from the **active projection** SHA and the **indexed SHA**. |
| Indexed SHA | Codesearch checkout ready for **this Workspace** at one git URL (Zoekt+SCIP as one). Independent per Workspace; not shared when two Workspaces use the same URL. |
| Path identity | The canonical identity of a git-backed knowledge unit is its path in the workspace tree. A move or rename is a new identity. Projection ids are derived from Workspace + path. Knowledge rows and codesearch indexes are **per Workspace** (not shared across Workspaces for the same git URL). |
| Confidence | Per-signal 0–1 **maximum** in the knowledge file. Hydrate copies it into the projection. Recall decays each signal then damped-combines (`α = 0.25` in code). Skill/ingest calibrate (~0.5 typical, ~0.7 strong). |
| Temporality | Optional `[valid_from, valid_to)` window. Missing `valid_to` = evergreen (source half-life). Missing `valid_from` is derived from the introducing git commit at hydrate, then persisted by a **job**. `e = 0` before `valid_from` and at/after `valid_to`. |
| AGENTS.md (workspace map) | Workspace-repository root file: display name in front matter; **one** semantic folder-structure section the ops job maintains (any heading the user chose). Keep folders that exist; drop dead links. Not this monorepo’s agent-instructions `AGENTS.md`. |
| Read-only Workspace | A Workspace whose desired workspace remote can be cloned and hydrated, but ctxpipe cannot commit/push to it. Chrome shows read-only with an error-specific fix. **Jobs** that maintain that URL are paused; hydrate, search, and workspace chat continue. Distinct from hydrate-failed (tree unreadable). |
| Workspace format | The layout version of a Workspace repository: one integer in `.ctxpipe/workspace.yaml` below the root folder. No file is format 0. Only an upgrade pull request or bootstrap changes it. Hydrate caches it in `workspaces.format_version`; git stays the truth. A format above the code, or a file that does not parse, makes the Workspace read-only (`format_ahead`, `format_invalid`). See [ADR-053](decisions/ADR-053-minor-upgrades-expand-only-sql-workspace-format.md). |
| Upgrade | Work that brings a Workspace to the current release. A git upgrade step raises the Workspace format by one, in an upgrade pull request; a re-ingestion upgrade runs a fresh ingestion of the source repositories, with a cost estimate. An operator click starts each one. A `workspace_write_jobs` row of kind `upgrade` tracks it. Required data work (for example retired workflow stubs) runs with no click. See [ADR-053](decisions/ADR-053-minor-upgrades-expand-only-sql-workspace-format.md). |
| Job sandbox | Retired for write jobs. Write jobs are typed workflows over captured git data and need no sandbox. Semantic merge is one model call and needs no sandbox too ([ADR-047](decisions/ADR-047-native-durable-write-workflows.md)). Ingestion steps run in an **ingest sandbox** ([ADR-052](decisions/ADR-052-ingestion-sandbox-skills-patches.md)). |
| Chat sandbox | One TanStack sandbox per conversation (`threadId` = conversation id), reused across turns and disposable: work is pushed to the conversation's **session branch**. Conversations run in parallel. See [ADR-048](decisions/ADR-048-native-postgres-sandbox-ownership.md). |
| Session branch | `ctxpipe/chat/<conversation>/<n>`: the git branch holding a conversation's edits. The durable state of a chat sandbox; Create PR opens a pull request from it. |
| Workspace base | A prepared sandbox start point for one Workspace: a snapshot (hosted) or an image (Docker) with the Workspace repository already cloned, so a new conversation does not clone in its first turn ([ADR-048](decisions/ADR-048-native-postgres-sandbox-ownership.md), [ADR-049](decisions/ADR-049-self-host-chat-sandbox-stock-docker.md)). |
| Ingest sandbox | The second TanStack sandbox definition (`workspace-ingest:<image>`, thread `ingest:<runId>:<shard>`), one for each shard of an ingestion run. It runs the **ingest skills** with closed egress and no long-lived credential. At most 40 per org, inside the 50 sandbox slots ([ADR-052](decisions/ADR-052-ingestion-sandbox-skills-patches.md)). Not a **chat sandbox**. |
| Ingest skill | An OpenCode skill folder (`SKILL.md`, `scripts/`, `schema.json`) under `apps/backend/ingest-skills/` that extracts one kind of knowledge from a source repository. Scripts decide first; the model judges only what scripts cannot see. The **skill bundle** is all skills, named by a content hash and copied to `/ctxpipe/skills` ([ADR-052](decisions/ADR-052-ingestion-sandbox-skills-patches.md)). |
| Ingest ref | A run-scoped git ref in the Workspace repository that holds the validated result of ingestion steps: `refs/ctxpipe/ingest/<runId>/<workspaceId>/shards/<shard>` and `…/assembled`. Only the write broker pushes it, never by force. Publish replays it on the default branch, then deletes it ([ADR-052](decisions/ADR-052-ingestion-sandbox-skills-patches.md)). |
| Context index | `<workspaceId>.index.json`: the list of existing knowledge units of a Workspace (path, kind, title, summary, links, sources, `owned`) that the host builds from the projection for an ingest step, so the agent updates or links to existing context instead of adding a copy ([ADR-052](decisions/ADR-052-ingestion-sandbox-skills-patches.md)). |
| Zoekt | Google's open-source code search engine, used for indexing and searching repositories |
| MCP | Model Context Protocol — AI tool interface exposed alongside REST APIs |
| Better Auth | TypeScript authentication framework used in the backend |
| Drizzle | TypeScript ORM (beta/v1 API) for PostgreSQL |
| React Aria | Adobe's accessibility-focused React component primitives |
| TanStack Start | Full-stack React framework with file-based routing (used in apps/ui) |
| source connector | Integration that authorises an external system and makes its content available to ctxpipe. Durable connectors are **git-native** (mirror or capture into the **Workspace repository**). MCP clients are not source connectors. See [source-connectors skill](../../.agents/skills/source-connectors/SKILL.md). |
| Source | What a Workspace reads: a linked code repository, or a scope in a dev tool or a docs tool (Linear teams, PagerDuty services, Notion pages, Confluence spaces, Slack capture). Tool and docs sources are entries in `.ctxpipe/sources.yaml` in the workspace repository ([ADR-050](decisions/ADR-050-workspace-sources-config-file.md)). UI: **Sources** in Workspace settings. Each source reads through a **Connector**. Decided 2026-10-12; replaces the CTX-536 "Connectors" section name. |
| Connector | An organization-level app connection that gives ctxpipe access to a provider: the GitHub App installation or an OAuth app (Linear, Notion, Slack, Atlassian, PagerDuty). One `connections` row ([ADR-018](decisions/ADR-018-unified-connections-table.md)). UI: the **Connectors** page. Not what a Workspace reads; that is a **Source**. |
| git-native | Connector pattern: write provider content as files in the **Workspace repository**, then ingest that repository. Config lives in git yaml (via PR); Postgres holds binding and secrets only. GitHub is the current rich adapter for PRs and commits. [ADR-022](decisions/ADR-022-linear-connector-git-native-mirror.md), [ADR-023](decisions/ADR-023-notion-connector-git-native-mirror.md). |
| context repository | Retired. Before Workspaces, the git repository (often GitHub `ctxpipe-context`) that received connector files under per-connector roots (`linear/`, `notion/`, `slack/`, `github/`, …). The **Workspace repository** receives them now ([ADR-031](decisions/ADR-031-github-pr-scoped-mirror.md) revision). |
| Cutover | Retired. Dest Workspaces for enabled Linear/Notion/Confluence/Slack git URLs were created **once** by SQL migrate (`INSERT workspaces` + `workspace_linked_repositories`). The `workspace-cutover` job and `org_workspace_cutover` table are gone. **Not** a step in add-workspace; later dests do not auto-mint a Workspace. |
| connections.config | JSONB on the unified `connections` row: identity, encrypted secrets, and sync/capture binding. Not a per-connector table. [ADR-018](decisions/ADR-018-unified-connections-table.md). |
| deployment-owned | OAuth app + webhook URL belong to **this** ctxpipe deployment (hosted or self-host). Organisations install that app; they do not get a ctxpipe-SaaS proxy. |
| self-host data boundary | Self-hosted customer tokens, webhooks, and source bytes stay on the customer’s deployment. Hard forbid: no ctxpipe-SaaS proxy, relay, gateway, or hosted OAuth app on that path. |
| File (graph) | Location node for a repo-relative path (`fil:${repositoryId}:${path}`). Not a document kind. Join for `DECLARED_IN` (instruction units, decisions), pull-request change edges, and `PART_OF` containment. [ADR-032](decisions/ADR-032-path-located-graph-edges.md), [ADR-033](decisions/ADR-033-graph-ontology-v2.md). |
| relation family | Group of graph predicates with one semantics: containment (`PART_OF`), provenance (`DECLARED_IN`), change (`TARGETS`, `ADDED`…), reference (`REFERENCES`, `MENTIONS`, `SUPERSEDES`), ownership (`OWNS`), cause (`INFLUENCES`). [ADR-033](decisions/ADR-033-graph-ontology-v2.md). |
| source file | One Markdown file under `sources/` (below the Workspace root folder) for each Workspace source. The front matter holds `provider`, `connection`, and the scope (GitHub: one `repository` and an optional `ref`); the body is an optional description that people own. The path is the source identity and the `workspace_sources.source_key`. Replaces `.ctxpipe/sources.yaml`. [ADR-050](decisions/ADR-050-workspace-sources-config-file.md) revision 2026-10-16. |
| provenance edge | `FROM_SOURCE`: an edge from a unit to the `Source` unit of each path in its host-set `sources` front matter. Only the `provenance` intent of `get_related` (or explicit `predicates`) walks it; default walks skip it because a `Source` node is a hub. [ADR-050](decisions/ADR-050-workspace-sources-config-file.md) revision 2026-10-16, [ADR-051](decisions/ADR-051-mcp-read-surface.md). |
| reference resolver | `domain/codeIngestion/referenceResolver.ts`: the single mapping from provider URLs, identifiers and repo paths to graph keys, shared by every extractor so the same real thing gets one node. |
| join density | Graph health metric: share of objects whose claims carry evidence from ≥2 extractors. Replaces nodes-to-edges as the north star. `GET /:orgSlug/api/v1/knowledge-graph/quality`. |

## Retired names (do not use in new copy)

| Retired | Use instead |
| --- | --- |
| Project (`proj_`) | **Workspace** (`ws_`); longer copy **Context Workspace** |
| Backing repository / backing repo | **Workspace repository** |
| Context repository | **Workspace repository** |
| Attached repository / attached repo | **Linked repository** |
| Attach / detach (repos) | **Link / unlink** |
| Project chat | **Workspace chat** |
| Serving store / derived store (when you mean the index) | **Projection** |
| Write sandbox | **Job sandbox** (retired) |
| Connectors (as the Workspace settings section) | **Sources**; **Connectors** names only the organization page of connected apps |
| Cutover (as a product step) | **Create workspace** (GitHub picker); uniqueness = that repo already has a Workspace |
