# P2-1 Unit title, source and updated_at

## What

- Migration `20261013022116_knowledge_unit_title_source`: nullable `title` and `source` on `workspace_knowledge_units`. The `updated_at` column was there; it now holds the last commit time of the path, not the row write time. The embedding write no longer changes it.
- `connectorMirrorRoot(path)` in `domain/codeIngestion/connectorMirrorPaths.ts`. `isConnectorMirrorPath` calls it, so there is one source of truth.
- `hydrateKnowledgeTree` sets `title` (front-matter `title`, else the first ATX heading outside a code fence), `source` (mirror root or `authored`), and `updatedAt`.
- `listMarkdownFilesAtGitSha` gives `lastCommitTimestamp` from the same history walk that gives the introducing commit (`--diff-filter=AMT`, newest first). The history buffer is now 128 MB.

## Why

ADR-051 section 8: search filters by source and time, and results show titles.

## Tests

- `knowledge-chunks.contract.test.ts` (real Postgres, real Git, hydrate workflow): all six mirror kinds and an authored unit get the right title, source and commit time. The reuse test also checks that an edited path gets the second commit time and an unchanged path keeps the first.
- `clone-tree.test.ts`: introducing and last commit time for an edited and an unchanged path.
- `hydrate.test.ts`: title rules (front matter, heading, fenced `#`, none), source, updatedAt.
- `connectorMirrorPaths.test.ts`: the root of each mirror kind; null for authored paths.
- Migration: applied on a fresh database, and on a database with a unit row from before (the new columns are null).

## Risks

- Units hydrated before this change keep null `title` and `source` and a row-time `updated_at` until a new commit hydrates the Workspace. A backfill re-hydrate is a follow-up.
- The history walk now reads modifications as well as additions. A very long mirror history can approach the 128 MB buffer.
