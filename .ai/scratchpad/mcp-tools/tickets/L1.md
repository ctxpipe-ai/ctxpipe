# L1 Remove LangGraph

## What
- The nine ingestion node files and `extractInstructionUnits.ts` read the run config with `AsyncLocalStorageProviderSingleton.getRunnableConfig()` from `@langchain/core`. This is the same call that `getConfig()` made.
- Removed `@langchain/langgraph`, `@langchain/langgraph-checkpoint` and `@langchain/langgraph-checkpoint-postgres` from `apps/backend/package.json`.
- Removed `db/migrate-checkpoints.ts`, its test, and every caller (`migrate.ts`, `scripts/db-migrate.sh`, three CI workflows).
- New migration `drop_langgraph_checkpoint_tables` drops `checkpoints`, `checkpoint_blobs`, `checkpoint_writes` and `checkpoint_migrations` (`IF EXISTS`, custom Drizzle migration; the tables were never in the Drizzle schema).

## Why the patch stays
`langchain` (used for `createAgent` and `tool`) installs `@langchain/langgraph` as a dependency. Without the patch, its zod type augmentation breaks typecheck (about 600 errors, for example `.openapi` missing on zod objects). The patch and its `pnpm-workspace.yaml` entry stay until L2b moves `createAgent` off LangChain. Then delete both.

## Tests
- Ingestion and graph suites (`src/graphs`, `src/domain/codeIngestion`): 212 passed, 1 skipped (existing).
- Migration applied on a fresh database, and the four tables dropped when present.
- `pnpm install --frozen-lockfile`, `pnpm typecheck`, test policy, biome: pass.

## Risks
- Production still holds the old tables until the migration runs. Their data is unused.
