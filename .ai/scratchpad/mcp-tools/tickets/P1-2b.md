# P1-2b Consent org picker and Connected apps page

## What

- Consent page: one check box for each org of the user. The current org is ticked. Allow stays off until at least one org is ticked. The page sends the ticked org ids, comma-separated, in `x-ctxpipe-oauth-organization`. The grant's org set becomes exactly that list.
- Backend consent: `parseOAuthConsentOrganizationIds` reads the header. `resolveOAuthConsentOrganizationIds` refuses the consent (`organization_required`, 400) when the list is empty or when one org is not a membership. `resolveOAuthGrantReference` takes `organizationIds`.
- The "Change organisation" link and `getOAuthOrganizationChangeHref` are removed; the picker replaces them. The `/.auth/select-organization` route stays for the authorize flow.
- Routes under `/api/v1/me/connected-apps` (OpenAPI + Zod), signed-in session only (an OAuth token or an API key gets 403):
  - `GET /`: the user's `ogr_*` grants with client name, scopes, and org set ∩ live membership.
  - `PUT /{grantId}/organizations`: `{ organizationIds }` with at least one id. Each added org must be a membership (400). Another user's grant or an unknown id gives 404.
  - `DELETE /{grantId}`: 204, through `revokeOAuthGrant`; 404 when the grant is not the user's.
- Account settings: a "Connected apps" view (`/.auth/account/connected-apps`) with edit (org picker in a dialog) and revoke (confirm dialog).
- MCP: for an OAuth connection, `org_not_found` adds a pointer to `{AUTH_BASE_URL}/.auth/account/connected-apps`. The hint depends only on the kind of connection, so the text for an unknown org and for an org outside the grant stays the same.

## Why

ADR-051 and the CTX-586 plan: the user selects orgs at consent and edits or revokes them later with no new connection. The security review asked for the Connected apps hint on `org_not_found`.

## Tests

- `routes/v1/me-connected-apps.integration.test.ts` (real Postgres): own grants only, legacy consent not listed, exact set, empty set refused, non-member add refused, another user's grant and unknown grant 404 with no change, revoke deletes only own consent and tokens, personal API key 403, no credential 401.
- `auth/oauth-grant-consent.integration.test.ts`: the real consent flow with two ticked orgs gives a grant with both; a ticked org with no membership gives 400 and no consent.
- `auth/oauth-organization.test.ts`: header parse and the multi-org consent rules.
- `mcp/framework.integration.test.ts`: an opaque OAuth token gets the Connected apps hint, with the same text for an unknown org; an API key gets no hint.
- Storybook play tests (golden): `ConsentOrgPicker`, `ConsentNeedsOneOrg`, `ConsentWriteOffByDefault`, `ConnectedAppsEditOrgs`, `ConnectedAppsRevoke`; also `ConsentReadOnly`, `ConsentWriteOnly`, `ConsentOrgsUnavailable`, `ConnectedAppsEmpty`. They replace the jsdom `OAuthConsent.test.tsx`.

## Risks

- Legacy consents (an org id as reference) are not listed. They keep one org and cannot be edited; the user connects again to get a grant.
- The Better Auth account sidebar on the Account and Security views does not show "Connected apps". The API Keys and Connected apps views use `AccountSettingsNav`, which does.
- The edit check boxes list the user's current orgs. An org in the set that the user left is dropped on the next save; it gave no access before.
