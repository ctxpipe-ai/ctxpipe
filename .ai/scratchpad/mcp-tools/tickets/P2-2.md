# P2-2 Knowledge chunks with pgvector and tsvector

## What

- Migration `20261013022209_workspace_knowledge_chunks`: `unit_id`, `org_id`, `workspace_id` (foreign key, cascade), `projection_sha`, `ordinal`, `text`, generated `search` tsvector (GIN), `embedding vector(2000)` (HNSW, cosine), `chunk_hash`. Primary key `(unit_id, projection_sha, ordinal)`; indexes on `(workspace_id, projection_sha)`, `(workspace_id, chunk_hash)`, `org_id`. RLS `org_isolation` like the unit table (ADR-042). The default privileges of `ctxpipe_app` give the grants.
- `unit_id` has no foreign key: old chunks must stay in the activation transaction after the unit rows go, so that new chunks can copy their embeddings.
- Chunk rule (`domain/workspaces/knowledge-chunks.ts`): one chunk per heading section; a section over 512 tokens (about 2,048 characters, no tokenizer) splits on blank lines, then on length. No merge across headings, so an edit changes only its own chunk hash. Hash: SHA-256 of the text.
- `commitHydrateProjection` writes the chunks of the new SHA in the activation transaction, copies embeddings by hash from any chunk of the Workspace, and deletes the other rows. A replay of the same SHA keeps an embedding when the hash is unchanged.
- After activation, `embedKnowledgeChunks` embeds the distinct hashes with no embedding (64 per model call, outside the org database context). `persistUnitEmbeddings({ revision })` sets each unit embedding to the mean of its chunk embeddings in SQL. Units need no model calls of their own. `embedHydrateUnits` is gone.
- No chunk text goes into a step output. The embedding work is not a step, as before.

## Why

ADR-051 section 8: indexed search per Workspace, and no new model calls for unchanged text.

## Tests

`knowledge-chunks.contract.test.ts` (4; real Postgres as `ctxpipe_app`, real Git, msw embedding handler with a call counter):

- A second hydrate with one changed section embeds only that chunk; unchanged chunks keep their old vectors; a duplicate section in another unit is embedded once; the unit embedding is the mean. Without the hash copy, this test fails (checked).
- Chunks of the active SHA stay while a newer revision is captured, and stay when a newer hydrate loses its activation (CAS discard).
- RLS: another org reads no chunk, cannot insert a row for the owner org, and deletes nothing.

`knowledge-chunks.test.ts` (5): chunk boundaries, fences, the cap, edit locality, rows and hashes. `hydration.contract.test.ts` uses the new `persistUnitEmbeddings` signature.

## Risks

- Workspaces active before this change have no chunks until their next hydrate (same follow-up as P2-1).
- The hash covers the text only. A change of the embedding model must clear the chunk embeddings.
- Chat retrieval still reads unit embeddings; these are now chunk means, not one embedding of the whole body.
