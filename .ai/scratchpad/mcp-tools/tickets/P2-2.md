# P2-2 Knowledge chunks with pgvector and tsvector

## What

- Migration `20261013061102_knowledge_unit_metadata_and_chunks`: table `workspace_knowledge_chunks` with key `(workspace_id, unit_id, chunk_hash, occurrence)`, and `org_id`, `ordinal`, `start_line`, `end_line`, `text`, generated `search` tsvector (GIN), `embedding vector(EMBEDDING_DIMENSIONS)` (HNSW, cosine). `workspace_id` has a cascading foreign key. Index on `(workspace_id, chunk_hash)` and `org_id`. RLS `org_isolation` like the unit table (ADR-042). The default privileges of `ctxpipe_app` give the grants.
- No `projection_sha` column: rows belong to the active projection and stay across SHAs. `unit_id` has no foreign key, because units are replaced in the activation transaction.
- Chunk rule (`domain/workspaces/knowledge-chunks.ts`): one chunk per heading section; a section over 512 tokens (about 2,048 characters) packs paragraphs up to the cap; a longer paragraph splits at code points. Fences close only with the same character, at least the opening length, and no info string. The text starts with the unit title and the heading path. Lines are file lines (after front matter). Hash: SHA-256 of the embedding model id and the text.
- Activation (`commitHydrateProjection`): reads the existing keys, inserts new chunks, copies embeddings by hash into rows with none, updates the line columns of moved chunks, and deletes gone chunks. Unchanged chunks get no write.
- After activation, `embedKnowledgeChunks` embeds distinct hashes with no vector (64 per call, outside the org database context). It throws when an update changes no row. `persistUnitEmbeddings({ revision })` sets unit embeddings to the mean of their chunks and refuses (throws, so the embedding phase is failed and retried) while a chunk has no vector or a unit with text has no chunk.
- Backfill: the projection snapshot has `chunksMissing`. When the active projection has a unit with text and no chunk rows, hydrate treats the revision as not active and publishes it again (Postgres, embeddings, graph, index).
- No chunk text goes into a step output.

## Why

ADR-051 section 8: indexed search per Workspace, and no new model calls or index writes for unchanged text.

## Tests

`knowledge-chunks.integration.test.ts` (6; real Postgres as `ctxpipe_app`, real Git, hydrate workflow, msw embedding handler with a call counter):

- Edit of one section: only that chunk is embedded; the other rows keep their `ctid` and vector (no write). A line added above moves the later chunks: their lines change, their vectors stay, and only the edited chunk is embedded. A duplicate section in another unit is embedded once. The unit embedding is the mean. Checked to fail when every kept row gets an update.
- Old chunks stay while a newer revision is captured and when a newer hydrate loses its activation (CAS discard).
- Backfill: a projection with no chunks and null `title`/`source` gets chunks, metadata, vectors, and ready embeddings on a run of the same revision; the next run embeds nothing. Checked to fail without `chunksMissing`.
- `persistUnitEmbeddings` refuses with a NULL chunk vector and with no chunks.
- RLS: another org reads no chunk, cannot insert a row for the owner org, and deletes nothing.

`knowledge-chunks.test.ts` (8): fences (4-backtick block with 3 backticks inside, tilde, info string), heading path and lines, packing, emoji at a boundary, edit locality, title prefix, occurrence, and the model in the hash.

Migration: applied on a fresh database, and on a database with a unit row from before.

## Risks

- The backfill runs the graph and index phases once more for each Workspace from before this change, and it needs a hydrate run of the revision to happen.
- Chat retrieval still reads unit embeddings, which are now chunk means (P2-3 moves chat to chunks).
