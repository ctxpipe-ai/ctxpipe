# P2-6 Org-level code search and SCIP fan-out

## Rules

- `resolveCodeScope` (`apps/backend/src/mcp/framework/org-code.ts`) takes handles from the org. A Workspace only limits the scope. A repository that several Workspaces link occurs once. Exclusion runs before any request.
- Each `CodeRepository` has `branch` and `sha` from its published checkout, so a response can state what it served.
- `skipped` reasons:
  - `not_indexed`: no published checkout, a codesearch 404, or a graph answer with `index: "missing"`.
  - `failed`: a request error, the call deadline, or `index: "unreadable"`.
  - `over_limit`: a repository after the first 10 in handle order. The result then has a `hint` to narrow the call with `repositories` or `workspace`.
- A codesearch 400 gives `invalid_argument` with the codesearch detail. Graph anchors are checked before the fan-out.
- Text search is one Zoekt request over the full scope. `literal` quotes the text with `zoektLiteralQuery`. `regex` sends the text as a Zoekt query. A rejected query gives `invalid_argument`, with no literal retry. Any other failure gives a retryable `internal` error.
- Each request asks for `limit + 1` results. `truncated` and `nextOffset` show when more results exist.
- Merge: rank 0 of each repository in handle order, then rank 1, and so on.
- Load: at most 10 repositories for each call, at most 20 SCIP or structural requests for each process (`SCIP_PROCESS_LIMIT`), one 20 s deadline for each call, and 3 short retries.
- Codesearch `/graph` has the primitive `find_references`: each occurrence of the symbol without the Definition role.

## Decisions

- The coordinator decided that the 10-repository limit is a hard cap for each call.
- Search uses the published checkout, not the Workspace revision (ADR-051).
- Codesearch has no admission limit for SCIP loads, so the backend uses a semaphore for each process (ADR-051).
