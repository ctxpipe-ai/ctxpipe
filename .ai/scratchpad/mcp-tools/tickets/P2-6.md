# P2-6 Org-level code search and SCIP fan-out

## What

- `apps/backend/src/mcp/framework/org-code.ts`:
  - `resolveCodeScope(org, { workspaceId?, repositories?, excludeRepositories })` gives the repositories to search, the excluded handles, and `skipped` (`not_indexed`).
  - `searchCodeText` sends one Zoekt request over the scope (through `codeSearch`).
  - `findSymbolAcrossRepositories` (`/graph`) and `structuralSearchAcrossRepositories` (`/structural-search`) fan out with at most 10 requests at once (`SCIP_FAN_OUT_LIMIT`).
- `listOrgRepositoryUrls(org, workspaceId?)` can now limit the links to one Workspace. It stays the only reader of the two link stores.
- `tools/structuralSearch.ts`: `codesearchStructuralSearchJson` gives parsed JSON. The TOON tool wraps it and its behavior does not change.

## Why

ADR-051 §4 and §7: code tools resolve repositories at org level, and they drop excluded repositories before any request.

## Rules

- Handles come from the org. A Workspace only limits the scope. A repository that several Workspaces link occurs once.
- A repository is `not_indexed` when it has no published checkout (the same join as `codeSearch`).
- When a fan-out request fails, that repository is `skipped` with the reason `failed`. The log has no error text, because that text can echo the query.
- Merge: rank 0 of each repository in handle order, then rank 1, and so on. The order does not change with the arrival order. `pageWithinBudget` applies the cap. The fan-out sends `limit` to each repository.
- A failed Zoekt request gives a retryable `internal` error. One Zoekt request covers all repositories, so no single repository caused the failure.

## Tests

`org-code.integration.test.ts` (real Postgres, msw codesearch with request capture, 6 tests):

- An excluded repository (as a handle and as an SCP URL) is in no request.
- A repository that two Workspaces link is searched once.
- A Workspace limits the scope.
- One failing repository gives `skipped`.
- 12 repositories have a peak of 10 requests in flight, and each repository gets a request.
- The merge order is stable, and the limit and the token budget apply.

Mutation checks: when the exclusion, the fan-out limit, or the merge is removed, a test fails.

## Risks

- "At most 10 repositories" means 10 requests at the same time. All repositories in scope are searched. If the plan means a hard cap of 10 repositories, add a `skipped` reason for the rest.
- Search uses the published checkout of each repository, not the Workspace revision.
