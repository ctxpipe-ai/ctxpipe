# L2a: Host model provider

Issue: [CTX-614](https://linear.app/ctxpipe/issue/CTX-614).

## Scope

Move host model calls to the TanStack AI adapter interface. Keep the existing
provider settings, native Bedrock Converse calls, and forced-tool schemas.
Keep ingestion and Slack on the legacy provider for their later migrations.

The published TanStack adapters stream plain text calls. Their Bedrock adapter
also omits arbitrary additional model fields. A small host adapter must retain
non-streaming calls and the existing parameter mapping.

## Proof

Use MSW at the HTTP boundary for each provider. Check text, structured output,
request parameters, authentication, cancellation, and Langfuse generations.
Use the branch database as `ctxpipe_app` for the conversation title tests.

## What changed

- `getModel` returns a `HostTextAdapter` (TanStack AI). OpenRouter, OpenAI-like
  and Azure send one non-streaming chat completion. Bedrock sends one native
  Converse call. Existing parameter mapping stays.
- Structured replies retain `agents_md_folder_list` and
  `workspace_semantic_merge`. The collision enum uses `structured_output`.
  The adapters accept only the requested tool. TanStack validates its arguments
  against the caller's Zod schema.
- Every request is one Langfuse generation. Callers pass `name`.
- Callers moved: commit subject, conversation title, chat tool judge,
  folder list, semantic merge, unkeyed collision enum.
- Ingestion and Slack use `legacyModelProvider.ts` until CTX-584 and L2b.
- Cancellation: the adapters read `options.request.signal`.
- OpenAI-compatible calls retain six retries for transient failures.
  The shared retry helper accepts a signal to stop backoff at the deadline.
- Hydrate retains the shared embedding API. Workspace chat tools have no direct
  host model call, so these two plan items need no caller change.

## Tests

- Red: the original host text tests failed because the provider returned a
  LangChain model. The retry tests failed on HTTP 429 and 503. The backoff
  cancellation test failed because cancellation waited for the retry delay. Tests for an
  unrelated response tool also failed before the adapter checked its name.
- The existing worker recovery test exposed the semantic tool name change.
  The adapter now retains the original name; the worker recovery suite passes.
- Focused suite: 121 tests pass in 14 files. This includes the host provider
  tests and the caller matrix (all six callers on OpenRouter, Bedrock, and
  Azure). Conversation titles use real Postgres as `ctxpipe_app`.
- Final backoff fix: 38 tests pass in four files. These include all 18 host
  provider tests, 15 retry helper tests, the caller matrix, and commit deadlines.
- Native maintenance and worker recovery: nine tests pass in two files.
  These use real Git, Postgres, and FalkorDB.
- Test policy: exit 0 (757 test, story, and config files; 49 command files).
- Full `pnpm typecheck`: exit 0 with only acknowledged diagnostics.
- Biome: exit 0 on the changed TypeScript and JSON files.

## Risks

- Tests use MSW for paid providers. No paid provider request was made.
- Zoekt is not installed locally. Tests that require `zoekt-webserver` remain
  for CI; no test was disabled.
- `@smithy/node-http-handler` is a direct dependency so Bedrock uses the Node
  transport under every runtime.
