# P1-3 MCP tool framework

## What

The shared base for the seven read tools of ADR-051, under `apps/backend/src/mcp/framework/`:

- `tool-registry.ts`: `defineMcpReadTool` and `registerMcpReadTools`. Each tool gets a `title`, the read annotations, an input schema with `org` first, an output schema, and `_meta["anthropic/alwaysLoad"]` when the tool asks for it. The registry applies the in-flight limit, resolves `org`, runs the tool in the RLS context of that org, and maps errors.
- `call-org.ts`: `resolveCallOrg(slug)` and `listCallOrgs()` for the principal of the request. They call `auth/call-org.ts`.
- `call-workspace.ts`: `resolveCallWorkspace`, `requireServed` (`workspace_not_ready`), `listOrgWorkspaceSlugs`, and `loadOrgRepositoryHandles`.
- `repository-handles.ts`: `owner/name` handles, `host/owner/name` on a collision, `resolve`, and `exclusion` (handle, SSH, HTTPS, `ssh://`, `.git`). All forms go through `normalizeWorkspaceRepositoryUrl`.
- `refs.ts`: `parseRef` and `formatRef` (`path` or `handle:path`).
- `cursor.ts`: an opaque cursor bound to the projection SHA (`stale_cursor`) and to the query (`invalid_cursor`).
- `budget.ts`: token estimates, `pageWithinBudget`, and `truncateText`.
- `tool-result.ts`: TOON text and `structuredContent`, with a hard cap of 24,000 characters.
- `tool-errors.ts`: the error codes.
- `instructions.ts`: dynamic instructions. The rules come first and fit in 512 characters. The org and Workspace list stops at a whole slug and keeps the total under 2,048 characters.
- `server-discover.ts`: a `server/discover` handler (stateless revision).
- `in-flight.ts`: 8 calls in flight for each principal in one process.

On the real `/mcp`, `routes/mcp.ts` replaces `withNetworkOrgContext` with `withMcpDefaultOrg`. Each read tool takes its org from the `org` argument and ignores `?orgSlug=`. A `?orgSlug=` that the principal cannot use still gets 404. With no `?orgSlug=` and several allowed orgs, the request has no default org.

## Why

- ADR-051 §3–5 and CTX-586 design v2 §7.1.
- A tool error does not put `{ code, message, retryable }` in `structuredContent`. The MCP SDK `Client` checks `structuredContent` against the output schema of the tool, also when `isError` is true. The error goes in the TOON text and in `_meta["ai.ctxpipe/error"]`.

## Not done here, by plan

- No tool of the seven is registered. `ctx_advisor` stays. Production `/mcp` does not send instructions yet (`registerMcpRoutes` takes `instructions`). Phase 3 turns on both in one release.

## P1-2a interface

`auth/call-org.ts` on this branch is a stand-in. It has the exports of the P1-2a file (`CallPrincipal`, `CallOrg`, `CallOrgResult`, `callPrincipalFromContext`, `resolveCallOrg`) and reads the one-org grant of today. It adds `listCallOrgs(principal)`, which the instructions need. At the merge, take the P1-2a file and add `listCallOrgs` to it (grant set ∩ live membership, in slug order).

## Tests

- Unit: `repository-handles`, `refs`, `cursor`, `budget` (with `toolSuccess` and `toolFailure`), `instructions`, `in-flight`.
- `mcp/framework.integration.test.ts`: real Postgres, the real `/mcp` auth chain, and the MCP SDK `Client`. It covers instructions on `initialize` and `server/discover`, 50 Workspaces in 3 orgs, a stable `tools/list`, slug resolution, the same error for a foreign and an unknown org and Workspace, `workspace_not_ready`, exclusion by four forms, a cursor walk and `stale_cursor`, the in-flight limit, the `internal` error, and a `?orgSlug=` for org A that does not change a call that names org B.
- `routes/mcp.conformance.test.ts`: a framework tool in the conformance server, MCPJam conformance, and an SDK `Client` check.

## Risks

- The in-flight limit is for each process. Several replicas allow more calls.
- Without `?orgSlug=` and with several allowed orgs, `ctx_advisor` has no org and fails with a tool error. Old clients send `?orgSlug=` or have a one-org grant.
