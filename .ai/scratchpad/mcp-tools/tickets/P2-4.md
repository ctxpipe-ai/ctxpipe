# P2-4 Graph projection v2

## What

- `domain/workspaces/graph-projection.ts`: the new `writeWorkspaceRevisionGraph(graph, { revision, units })` writes one revision graph. `projectWorkspaceGraph` calls it.
- Each `WorkspaceKnowledgeUnit` node has `path`, `degree`, `inDegree`, and `outDegree`. One Cypher statement counts the edges after the edge write. Thus a claim without a target unit does not count.
- Each unit order gives the same graph.
- `workspaceGraphRevisionKey` hashes `{ projectionVersion: 2, revision }`. Version 1 hashed the revision alone.
- `platform/graph/indexes.ts`: `ensureWorkspaceGraphIndexes(graph, provider)` holds the index DDL for each engine (PR #350 idea 3). FalkorDB: composite `(projectionKey, id)`. Neo4j: `IF NOT EXISTS`. Neptune: none. An "already indexed" or "already exists" error is ignored.

## Why

Bounded reads (P2-5) and relevance scoring (P3-5) need the node path and hub size without a full graph load. A new version key makes the existing graphs of ready revisions not found. The graph route then marks the graph lost and starts a rebuild, which writes version 2 (one re-projection, approved by the CTO).

## Tests

`graph-projection.integration.test.ts` on live FalkorDB (5 tests): properties on a hub fixture; the same graph in two unit orders; a second write of a revision gives the same result; a complete version 1 marker reads as missing and a version 2 write reads; the index DDL runs twice and gives one index.

## Risks

- Version 1 nodes stay in FalkorDB after the rebuild. See `graph-gc.md`.
- The Neo4j DDL has no live test. Memgraph has no index.

## Review follow-up

- Memgraph gets no index DDL. The Bolt client sends each statement in a managed transaction, and Memgraph refuses index DDL there. No live Memgraph test proves an auto-commit path. An index failure logs a warning and the projection continues.
- `domain/workspaces/graph-rebuild.ts`: `readOrRebuildWorkspaceGraph` is the read path for the graph route, the chat graph tools, and the MCP tools. A pending or lost graph gives `WorkspaceGraphBuildingError`; a lost graph also starts one rebuild (`rebuildLostWorkspaceGraph`). Chat gets a `graph_building` retry message.
- The tip check calls `rebuildWorkspaceGraphWhenMissing` for each Workspace, one at a time. A ready graph without a marker under its key gets one rebuild. This starts the approved re-projection after deploy without a graph read.
- `workspaceGraphNodes` sets `path`. The writer does not sort; readers order by id in Cypher.
- `n.degree` counts raw signals (see the P2-5 and P3-5 notes). Garbage collection of old keys: `graph-gc.md`.
