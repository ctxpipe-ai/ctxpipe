# P1-4 Correlation and telemetry

## What

- `apps/backend/src/mcp/correlation.ts`: `runMcpToolCall({ toolName, extra, orgSlug }, fn)` is the hook for each tool call. The P1-3 framework calls it once for each `tools/call`. It:
  - reads the conversation id from `_meta["ai.ctxpipe/conversationId"]`, then `x-ctxpipe-conversation-id`, then baggage `ai.ctxpipe.conversationId`, then `_meta["openai/session"]`, then the `session_id` of the `x-codex-turn-metadata` header;
  - reads the turn id in the same order (`ai.ctxpipe/turnId`, `x-ctxpipe-turn-id`, baggage `ai.ctxpipe.turnId`, Codex `turn_id`);
  - accepts an id only when it matches `[A-Za-z0-9._:@-]{1,128}`;
  - continues the client trace when `_meta.traceparent` is valid W3C (version not `ff`, no all-zero ids, lowercase hex); the span links to the `POST /mcp` server span;
  - makes a connection key `mck_<sha256(principal, client)>`: the principal is the user or API key id, the client is the OAuth client id, else the client name (`io.modelcontextprotocol/clientInfo`, else the first User-Agent token);
  - sets `ctxpipe.mcp.{tool, call.id, connection.key, client.name, conversation.id, conversation.source, turn.id, turn.source, correlation.source, org.slug_hash}` on the tool span, the request log, and a forked attribution bag (child spans get them, sibling calls of a batch do not);
  - adds `_meta["ai.ctxpipe/callId"]` to each result, also to an error result.
- `observability/attribution.ts`: the new keys and `contextWithForkedAttributionBag`.
- `mcp/tools.ts`: `ctx_advisor` uses the hook (span name `mcp.tool ctx_advisor` stays).
- `ops/observability/clickhouse/schema/mcp-call-correlation.sql`: parameterized view `otel.mcp_tool_calls(from, to)` with `DerivedSessionId` (30 min gap) and `DerivedTurnId` (60 s gap) per environment and connection key.

## Why

ADR-051 section 9: group calls by conversation and turn with no tool arguments.

## Tests

- `mcp/correlation.test.ts` (9, real transport + McpServer + InMemorySpanExporter): each id source and the precedence, bad ids ignored, traceparent continues the trace, 7 malformed traceparents ignored, connection key per client and principal, no query text, path or repository URL on any span, call id on an error result.
- `observability/attribution.test.ts`: forked bag isolation.
- `mcp/transport.integration.test.ts`: the real `ctx_advisor` gets the turn id, the connection key and the call id.
- `ops/observability/clickhouse/schema/mcp-call-correlation.check.sh`: runs the view in `clickhouse-local` (production image) on fixture spans. Manual (Docker); CI does not run it. A changed turn gap makes it fail.

## Risks

- The Codex header shape (`session_id`, `turn_id`) is not verified.
- The view must be applied by hand as `otel`.
- `applyAttribution` also writes the request log; in a batch the last call wins on the log line.
