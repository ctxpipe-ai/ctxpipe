# T06 Patch validator

## What

- `apps/backend/src/domain/ingestion/patch-validator.ts`: `validatePatchStep` reads `files/` and `patch.json` of a step, builds the ops again from the staged tree, checks each op against the base commit, and applies the accepted ops on a temporary index. It returns the tree, the accepted ops, the rejections (path, rule, reason), and `complete` or `partial`.
- `patch.json` gives only the `baseBlob` of an update or delete and the list of deletes. A file in `files/` that is the same as the base blob is not an op. An op in `patch.json` with no staged file is ignored.
- Rules: `path`, `patch_json`, `base_blob_mismatch`, `ownership`, `additive_only`, `human_section`, `front_matter`, `evidence`, `link`, `content`, `size_cap`, `op_cap`, `delete_cap`, `heading_denylist`, `suspected_injection`.
- Exports: `validatePatchStep`, its types, `gitSourcePathExists`, and `fileOwnership` (the shared ownership predicate for T07).
- The extract-ingest and migration-export workflows import `isConnectorMirrorPath` from `connectorMirrorPaths.ts`, the one shared list. They now also skip `github/` and `pagerduty/`.
- `layout.ts` `KNOWLEDGE_KIND_FOLDERS` is the one kind-to-folder map. It now has `Decision` and `Team`, so the migration export writes Decision objects to `knowledge/decisions/`. The validator gets the folder-to-kind direction from it.

## Why

Concept sections 3.1, 4.3, and 6; ADR-052 section 2. The host never trusts the op list of the agent.

## Decisions in the code

- A file is `sole` (only this source in `sources`), `shared`, or `foreign`. Only a `sole` file gets a full write or a delete. A `shared` or `foreign` file gets only new claims and new list lines in a `## Related` section at the end. The host keeps the base front matter text and adds the new claims, so the comments and layout of a human file stay.
- Strict front matter for a full write: `kind`, `name`, `summary`, `claims` (`to`, `predicate`, `evidence: {path, kind: script|model}`), and the host fields. A create must not set a host field. An update must keep the host fields as they are at the base.
- The host checks evidence only for claims that are new or changed, so an old claim does not block an update.
- `instructions/` uses the existing kind `InstructionUnit`, so hydrate and the graph need no change.
- A create must not replace a base file or folder, and must not differ from another path only in case or Unicode form. A path must be in NFC form. After the apply, the host checks that the result tree differs from the base only at the accepted paths.
- A delete of a file with a human section is rejected. A human marker that the base does not have is rejected, in a full write and in an additive update.
- Headings come from `mdast-util-from-markdown`, so setext headings and headings in lists and block quotes are checked.
- The host refuses a symlinked `files/` folder or `patch.json`, checks file sizes before it reads them, and stops at 2 MiB for the staged tree.
- Rejection reasons do not quote staged text. Zod reasons give only the field and the issue code.
- External links (also `www.` links) go only to repositories that the Workspace knows: the source and `linkableRepositories`.
- The delete cap is `floor(20% of the files this source alone owns)`. When the step is over the cap, all its deletes are rejected.
- Links resolve against the result tree; the check repeats until no op drops out. Content, heading, and injection checks on an additive update look only at the added text.

## Tests

`patch-validator.test.ts` (39 tests, real git): one accept and one reject case per rule, `baseBlob` mismatch for update and delete, staged tree over `patch.json`, human-file body change rejected and a `## Related` line plus a claim accepted, caps, `partial`, stamps, idempotence (two runs give one tree; a stamped result staged again is not an op), and 25 seeded random steps that never change a file outside the allowlist. `layout.test.ts`: the `Decision` and `Team` folders.

## Risks

- The shared-file rules of section 5.3 (area files) are not here; the instruction-areas ticket adds them.
- A delete does not check links from other files to the deleted file.
- The heading denylist and the phrase scanner can reject honest text (for example "Copilot" in a heading). Tune them with real runs.
- With fewer than 5 owned files, the delete cap is 0 unless the root is gone.
