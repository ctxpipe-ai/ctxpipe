# T08 Run-scoped ingest refs

## What

- `apps/backend/src/domain/ingestion/ingest-refs.ts`: the ref job core.
  - Names: `refs/ctxpipe/ingest/<runId>/<workspaceId>/shards/<shard>` and `refs/ctxpipe/ingest/<runId>/<workspaceId>/assembled`. Each segment matches `[A-Za-z0-9][A-Za-z0-9_-]{0,127}`.
  - `pushIngestStep`: refuses a ref that is not of the job's run and Workspace, and a `baseCommit` (from `step.json`, T05) that is not the old tip (or the pinned revision for the first commit). Fetches the base, runs the T06 validator against it, and commits the accepted tree with parent = base, a fixed author and committer time (the run's `authorTime`), and the `Ctxpipe-Run`, `Ctxpipe-Step`, and `Ctxpipe-Bundle` trailers. Pushes with `--force-with-lease=<ref>:<oldTip or empty>`; the parent is the old tip, so each push is a fast-forward. After a failed push it reads the tip again: at the new SHA is a replay (success); moved is `IngestRefRefusedError`; unchanged (a lost ref lock) tries again, at most 3 times.
  - `pushIngestAssemble`: checks that each shard ref is at the given tip and descends from the pinned revision, applies the `diff-tree` ops of each shard on the pinned revision in a scratch index, and commits with the shard tips as parents (sorted by shard). A path that two shards change (case-insensitive) is `IngestAssembleConflictError`. A bad path, or more than 300 ops (the run cap of a Workspace), is refused. No per-step cap.
  - `findStepCommit`: the resume helper. It returns the tip when the trailers of the tip name this run and step, else null.
  - `deleteRunIngestRefs`: deletes the refs of one run in one Workspace. Idempotent.
  - `cleanUpIngestRefs`: an unfinished run keeps every ref. A finished run loses its refs; a shadow run keeps them for 7 days after `finished_at`. Only a ref of an unknown run, or with a bad name, goes by age (the tip commit time, more than 24 hours). It lists with the read remote and calls `pushRemote` (the write credential) only when a ref must go. It deletes each ref with a lease on its listed tip; a ref that moved is skipped.
- `models/ingestion-runs.ts`: `ingestionRunStates` (status, `finished_at`, `input.shadow`; org and workflow scoped; every version) and `orgHasRecentIngestionRun` (unfinished, or finished or created in the last 7 days).
- `models/workspace-sandboxes.ts`: `unfinishedOrgWorkflowRunIds` now counts every workflow version (the `version is null` filter is gone).
- `domain/ingestion/ingestion-run.ts`: `IngestionV2RunInput.shadow`. The global shadow constant is gone.
- `domain/workspaces/write-broker.ts`: `pushWorkspaceIngestStep`, `pushWorkspaceIngestAssemble`, `findWorkspaceStepCommit`, `deleteWorkspaceIngestRefs`, `cleanUpWorkspaceIngestRefs`. Admission comes before any credential: the run must be an unfinished ingestion v2 run of the org (one query); the Workspace must be bound in the org, `writable`, and at the job's `generation`, with a GitHub connection. Push and delete use the write token; resume and listing use the read token.
- `openworkflow/workflows/workspace-tip-check.ts`: the clean-up runs only when the org has an ingestion v2 run in the last 7 days, for each writable, GitHub-connected Workspace with access. A failure logs `workspace_ingest_ref_cleanup_failed` and does not fail the tip check.
- `routes/webhooks/github/github.ts`: a push to `refs/ctxpipe/` returns early, before the default-branch check.

## Why

Concept section 7, ADR-052 section 6, and the review of T08. The ref names differ from the first concept: git cannot hold `…/<workspaceId>` next to `…/<workspaceId>/<shard>`.

## Tests

- `ingest-refs.test.ts` (21, real git, bare remotes): names; first commit, trailers, fixed times, `main` unchanged, a default clone does not fetch the ref; the validator drops a rejected path; advance; replay gives the same SHA; wrong old tip (3 forms); a base commit that is not the old tip; racing pushes (50 runs, 0 failures); refs outside the run's names; resume after a crash after push; idempotent delete; clean-up keeps live runs' refs at 30 days of author age, deletes finished refs, keeps shadow refs until 7 days after finish, applies 24 hours only to unknown runs and bad names, skips a moved ref, and mints no token with nothing to delete; assemble of 3 shards (parents, tree, then a normal step on the assembled ref), replay, conflict on one path, wrong shard tip.
- `ingest-ref-broker.integration.test.ts` (5, real Postgres and OpenWorkflow runs): run states (unfinished, versioned, finished, shadow; foreign org and other workflow absent); the sandbox sweep counts a versioned run; recent-run check; the broker refuses an unknown, finished, or foreign run, a read-only Workspace, and an old generation.
- `github.test.ts`: a push to an ingest ref enqueues no tip check and no ingestion.
- 19 affected files pass (155 tests). `pnpm typecheck` exit 0. Test policy exit 0.

## Risks

- The broker wrappers have no success-path test against a GitHub remote; the T09 Docker contract covers them.
- A finished shadow run with no `finished_at` loses its refs at the next check.
- A ref of an org with no ingestion v2 run in 7 days stays until a new run starts.
- Assemble refuses any same-path overlap, also two equal results; T09 must route those to the semantic merge child.
