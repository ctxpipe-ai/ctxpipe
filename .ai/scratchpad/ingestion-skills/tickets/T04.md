# T04 Ingest tool bridge

## What

- `apps/backend/src/domain/workspaces/code-tools.ts` holds the shared read-only codesearch tool set: the input schemas, the tool definitions, `parseCodeToolArgs` (input check before any repository check), and `runCodeTool`, which runs one tool on one resolved checkout. A source checkout (`rev:<sha>`) reads with a source revision claim. A Workspace checkout (`ws:<workspaceId>:<sha>`, or the legacy `ws:<workspaceId>`) reads with a Workspace claim.
- `workspace-chat-tools.ts` uses this core. Chat keeps its policy (bound repositories, `list_repositories`, `codeSearch` with the projection snapshot) and its output. A chat `search` with no `repositoryId` or query gets `search_input_required`.
- `apps/backend/src/domain/ingestion/ingest-tools.ts`:
  - The bridge verifies the T03 `workspace-ingest-tools` capability (one per step, valid while the step holds the shard lock of an unfinished run). It reads the bound checkouts from the claims. There is no second token scheme.
  - The bridge refuses (403) a capability with an unknown checkout key, or with a repository that is not a repository of `claims.orgId`.
  - `ingestTools`: `list_checkouts` and the shared tools. Each call must give `repositoryId` and `checkoutKey`; a pair outside the capability gets `checkout_not_in_run`, and codesearch gets no request.
  - `ingestToolBridgeRoutes` at `POST /api/v1/workspace-ingest/tool-bridge`: stateless MCP JSON-RPC, mounted in `registerV1Routes`. It does not import `ingest-sandbox`.
- `tools/codesearchZoekt.ts`: `zoektSearchRepository` takes an optional Workspace revision; with it the search is scoped by claim and sends no `RepoIDs`.
- The T03 checkout list has no `.max(64)` cap: the capability length cap (8 KB, checked at mint) limits it.

## Why

ADR-052 section 7 and concept section 9: no codesearch index in the sandbox; the agent reads through the bridge, bound read-only to the run's checkout keys. One capability scheme for each shard step, with one revocation rule.

## Tests

- `ingest-tools.integration.test.ts` (real Postgres, real OpenWorkflow runs and shard locks, msw codesearch, through `registerV1Routes`), 8 tests: the tool list; `get_file`, `search`, `structural_search`, and `graph_find_symbol` on the source checkout with `repositoryRevisions`; a Workspace search with `workspaceRevisions` and no `RepoIDs`; six foreign checkout or repository cases refused with no codesearch call; 401 for a missing token, a changed payload with its old signature, a chat token, and a model capability; 401 for a well-signed capability of another run, shard, or org; 403 for repositories of another org; 401 after the lock is released and after the run is cancelled.
- `workspace-chat-tools.test.ts` (msw): bound read, legacy read, search, `search_input_required`, foreign repository.

## Risks and follow-ups

- T09 items are in the plan: the API origin for the bridge, the `tanstack` MCP server in the OpenCode config, and no rate limit for each shard yet.
- The native contract tests that use chat tools (`chat-projection`, `graph-workflow`, `index-workflow`) need `zoekt-webserver`. This host has no Go or Zoekt, so CI must run them.
