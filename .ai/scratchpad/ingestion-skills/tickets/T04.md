# T04 Ingest tool bridge

## What

- `apps/backend/src/domain/workspaces/code-tools.ts` holds the shared read-only codesearch tool set: the input schemas, the tool definitions, and `runCodeTool`, which runs one tool on one resolved checkout. A source checkout (`rev:<sha>`) reads with a source revision claim. A Workspace checkout (`ws:<workspaceId>:<sha>`, or the legacy `ws:<workspaceId>`) reads with a Workspace claim.
- `workspace-chat-tools.ts` uses this core. Chat keeps its policy (bound repositories, `list_repositories`, `codeSearch` with the projection snapshot) and its output.
- `apps/backend/src/domain/ingestion/ingest-tools.ts`:
  - `mintIngestToolToken`: an HMAC token (`AUTH_SECRET`) with the org, run, shard, sandbox key, and the bound checkouts (the source at its SHA, and each destination Workspace's repositories at their SHAs). The mint fails when the shard has no live sandbox.
  - `verifyIngestToolToken`: the signature, the claims, and the shard's ingest sandbox row. `destroy-sandbox` (and the org sweep) deletes that row, so it revokes the token. No new table or column.
  - `ingestTools`: `list_checkouts` and the shared tools. Each call must give `repositoryId` and `checkoutKey`; a pair outside the run gets `checkout_not_in_run`, and codesearch gets no request.
  - `ingestToolBridgeRoutes` at `POST /api/v1/workspace-ingest/tool-bridge`: stateless MCP JSON-RPC, so each replica can serve a call. A missing, forged, or revoked token gets 401. Mounted in `routes/v1/index.ts`.
- `tools/codesearchZoekt.ts`: `zoektSearchRepository` takes an optional Workspace revision; with it the search is scoped by claim and sends no `RepoIDs`.

## Why

ADR-052 section 7 and concept section 9: no codesearch index in the sandbox; the agent reads through the bridge, bound read-only to the run's checkout keys, with a run-scoped token that `destroy-sandbox` revokes.

## Tests

- `ingest-tools.integration.test.ts` (real Postgres, real unsandboxed ingest sandbox, msw codesearch), 7 tests: tool list; source read with `repositoryRevisions`; Workspace search with `workspaceRevisions` and no `RepoIDs`; six foreign checkout or repository cases refused with no codesearch call; 401 for a missing, forged, and wrong-secret token; no mint without a sandbox; 401 after `destroy()`.
- `workspace-chat-tools.test.ts` (msw), 4 new tests: bound read, legacy read, search, foreign repository. They pass on the old and the new chat file.

## Risks and follow-ups

- T09 wires the bridge: it mints the token after `ensure-sandbox`, gives the sandbox the URL on the backend origin, and puts the token in the run's vault (or the firewall) as chat does. A Docker sandbox must reach the backend origin; chat uses a per-run port for that today.
- The native contract tests that use chat tools (`chat-projection`, `graph-workflow`, `index-workflow`) need `zoekt-webserver`. This host has no Go or Zoekt, so CI must run them.
- Each bridge call reads the sandbox row once. ADR-027 budgets still limit codesearch load.
