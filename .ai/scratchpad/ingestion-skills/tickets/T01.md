# T01 Legacy sync-repository ingestion gate

## What
`enqueueLegacySyncRepositoryIngestion` (`openworkflow/legacy-sync-repository-ingestion.ts`) checks `connectionHasWorkspaceSources` (in `models/workspace-sources.ts`). If the connection has any source row, it starts no run. Otherwise it calls `enqueueRepositoryIngestionWorkflow`, whose return type stays non-null.

Callers of the wrapper: `linear-sync-{content,entity}`, `notion-sync-{content,entity}`, and the Linear, Notion, PagerDuty and Slack connector routes that start ingestion after they bind a sync repository.

Not gated, on purpose: GitHub pull-request mirror (writes to the Workspace repository), GitHub webhooks and manual re-index (not a sync repository), Confluence (no repository ingestion call).

## Why
A connection that moved to Workspace sources syncs through its Workspace. Ingesting its old sync repository too would duplicate work (CTX-584 decision 5).

## Tests
`enqueue-legacy-sync-repository-ingestion.integration.test.ts` (real Postgres): for each of linear, notion, slack and pagerduty, a connection with sources starts no run and a connection without sources starts one run. A second case shows that the sources of another connection do not gate.

A contract test (`linear-legacy-sync-gate-native.contract.test.ts`) runs the real Linear entity sync workflow: one ingestion run without sources, none with a `.ctxpipe/sources.yaml` source.

## Risks
The gate checks any source status, including `connection_missing`. The legacy path stays off until the source rows go.
