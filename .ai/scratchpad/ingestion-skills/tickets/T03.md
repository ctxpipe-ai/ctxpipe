# T03: Ingest capability and closed egress

## What

- **Capability** (`workspace-chat-run-capability.ts`): `mintWorkspaceIngestRunCapability` and
  `verifyWorkspaceIngestRunCapability`, purpose `workspace-ingest-model`. Claims: org, org slug,
  run, shard, and the owner of the shard lock. The capability is valid only while that owner holds
  the shard lock (`ingest:<run>:<shard>`, not expired) and the run is an unfinished
  `repository-ingestion-v2` run of the org. Each purpose has its own Zod schema with a literal
  `purpose`, so a chat capability never parses as ingest, and the reverse.
- **Model proxy** (`routes/v1/workspace-chat-openai.ts`): accepts the ingest capability and
  attributes the call to the shard thread.
- **Docker** (`ingest-sandbox-egress.ts`, `dockerIngestSandboxProvider`): `create` opens the
  shard's vault with `unmatchedHosts: "deny"` and `ingestCredentialRules` only (Git fetch of the
  source and destination repositories, the model proxy, the tool bridge). The container gets the
  vault's proxy session and CA. See "Review fixes" for `destroy`. `refreshIngestSandboxEgress` replaces the rules for a later step (same
  rule names). `setRunVaultRules` is the new Agent Vault helper for that.
- **Hosted**: see "Review fixes" (`ingestNetworkPolicy`, `vercelIngestSandboxProvider`).
- **Tokens** (`run-git-tokens.ts`): an ingest shard records its tokens under
  `ingest:<run>:<shard>:<label>:<window>`, apart from chat `run:` keys.
  `revokeFinishedIngestGitTokens` is the sweep's backstop for finished or unknown runs.
- **Webhook** (`github.ts`): a push to `refs/ctxpipe/*` returns early (no tip check, ingestion, or
  connector sync).
- `ingestSandboxThreadId` moved to `chat-lifecycle.ts`: the capability module must not import the
  OpenWorkflow client at import time.

## Why

ADR-052 and the T03 spike (`spikes.md`). The sandbox never pushes: the host pushes ingest refs.

- `ingest-sandbox-egress.test.ts`: `ingestNetworkPolicy` (fetch allowed; push, other repositories, unlisted backend paths go to the deny route; other hosts refused; chat stays open) and the deny route (403). `vercel-sandbox-provider.test.ts` (+1): the ingest firewall stays closed at step start and end.
- `ingest-sandbox-egress.integration.test.ts` (4): one token per connection; an uncovered repository throws and mints nothing; hosted tokens are swept after the run; the hosted provider refuses to start.

## Risks and follow-ups

- **Vercel was not tested live.** The proof is the policy object. Open question: does Vercel
  refuse a path with no rule on a listed host (for example `git-receive-pack` on github.com)? If
  it forwards it without a credential, GitHub refuses the push (no token), so the risk is low.
- Host dev (`agent-vault-dev`) does not force traffic through the proxy. The contract test moves
  the container to an internal network, as DinD and AWS do. T09 should not run ingest on host
  dev with real data.
- Sandbox Git URLs must be `https://github.com/<owner>/<name>.git` (with `.git`).
- T09 wires it: build the provider for the deployment's isolation, mint the capability per step
  while it holds the shard lock, call `refreshIngestSandboxEgress` (Docker) or `openTurn` and
  `closeTurn` (hosted), and call `destroy()` in `destroy-sandbox`.
- The ingest vault session TTL is the shard limit plus 15 minutes.

## Review fixes (round 1)

- **Vercel forwards unlisted paths.** A rule's `match` only limits its transform. The ingest
  policy is now `ingestNetworkPolicy`, built from the shared rule helpers (`hostRules`), not a
  mode of the chat policy. Each allowed host (github.com, and the backend host during a step) ends
  with a rule with no match that forwards to a 403 route (removed in round 2). `vercelIngestSandboxProvider` refuses to start until
  the T12 live check (`VERCEL_INGEST_EGRESS_PROVEN`). A hosted shard reads one GitHub connection.
- **Tokens per connection.** `ingestGitAccess` groups the repositories by GitHub connection and
  mints one token per group, each with its own fetch rules. A repository that its connection does
  not cover (no installation, or another owner) throws at create. The tokens have the read
  permissions of a Workspace read token (contents, issues, pull requests, metadata); the egress
  rules allow only Git fetch.
- **Open egress.** `create` runs a probe in the container: a direct connection (`--noproxy`) to a
  public IP must fail. Otherwise `create` deletes the container and the vault, revokes the token,
  and throws. The `network` option moves the container to an internal network.
- **Destroy** deletes the container and the vault, and revokes the tokens in `finally`. A revoke
  that fails is logged and left; `revokeFinishedIngestGitTokens` revokes it after the run.
  A vault that `destroy` could not delete is deleted by `sweepRunVaults` (after its age limit).
- **Hosted tokens** are stored under `ingest:<run>:<shard>:vercel`, so the same sweep revokes them.
- **Refresh** replaces the whole rule set (`replaceAll`): a repository that a later step does not
  list cannot be fetched.
- **Attribution.** The capability has the workflow `step`. The model proxy attributes an ingest
  call with `ctxpipe.ingest.run.id`, `ctxpipe.ingest.shard`, and `ctxpipe.ingest.step`, and sets no
  conversation id (no consumer reads `ingest:…` as a conversation now).
- `publishPorts` is an option of the Docker ingest provider (for `opencode serve` in T09).
- GitHub mint and revoke are msw handlers (`test/ingest-github.ts`), not injected functions.
- **A key per purpose.** Each capability is signed with `HMAC(AUTH_SECRET, "ctxpipe:capability:" +
  purpose)`, not the raw secret (which also signs codesearch JWTs). A chat capability in flight at
  deploy fails once.
- **Tool-bridge purpose for T04.** `workspace-ingest-tools` (`WorkspaceIngestToolsClaimsSchema`,
  `mintWorkspaceIngestToolsCapability`, `verifyWorkspaceIngestToolsCapability`): the step claims
  and the bound checkouts (`repositoryId`, `checkoutKey`, `sha`). It ends by the same rule as the
  model capability (`ingestShardIsHeld`).

## Review fixes (round 2)

- The ordered deny rule is removed: the Vercel API splits credential rules and forward rules, so it
  cannot hold. `ingestNetworkPolicy` keeps only the credential rules (no `"*"`), and it is not
  closed. T03b (backend egress proxy) replaces it. The hosted provider still refuses to start.
- The Docker probe checks HTTP and HTTPS to a public IPv4 address and HTTP to a public IPv6
  address. Only the DinD and AWS sandbox hosts and internal Docker networks are supported.
- `destroy` deletes the vault and revokes the tokens in nested `finally` blocks.
- Mutation check: with each fix of items 1 to 6 and 13 removed, its test failed.
